## 编码与工程偏好

- 极简优先（ponytail 阶梯）：停在第一个成立档位——投机需求直接跳过（YAGNI）、先复用已有 helper、标准库优先、平台原生特性优先（DB 约束>CSS>JS）、不为几行代码新增依赖、能一行写完就一行。
- 最短可运行 diff 获胜，删除优于新增；Bug 修根因不修症状，改函数前 grep 所有调用方，在共享路径修一次。
- 外科手术式修改：每行改动可追溯到用户请求，不顺手"改进"相邻代码；只清理自己制造的孤儿引用。
- 刻意简化用 `ponytail:` 注释标明天花板与升级路径；非平凡逻辑留一个最小可运行检查，不引框架。
- 永不简化掉：信任边界输入校验、防数据丢失的错误处理、安全措施、无障碍基础、用户明确要求的东西。
- 目标驱动：先定义可验证成功标准再动手；长任务 checkpoint 确认；失败可见，禁止静默跳过或谎报成功。
- 上下文管理：开放式搜索/多轮 grep/大文件派 subagent，主 agent 只接收结论；已知路径小文件精确编辑直接做。
- 完整工程行为规则真源见 ~/.agents/AGENTS.md。
