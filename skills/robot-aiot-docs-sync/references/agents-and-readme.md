# Step 3-4: AGENTS 与 README

## Step 3: 生成或更新 AGENTS.md

`AGENTS.md` 面向 AI 助手，目标是让 agent 不必先读完整个仓库也能开始有效工作。

### 更新原则

1. 先读取已有 `AGENTS.md`
2. 保留项目专属规则与已有 Agent 指南章节
3. 仅更新过时的结构、入口、命令和架构说明

### 应包含的内容

1. 项目概览
2. 仓库结构
3. 入口点
4. 开发环境搭建
5. 关键规范
6. 架构说明
7. Agent 工作指引

## Step 4: 生成或更新 README.md

`README.md` 面向人类开发者、用户和贡献者，以中文为主，技术名词保留英文。

### README 核心原则

1. 首屏 30 秒内能说明价值、适用人群和最短安装方式
2. 所有命令、路径、示例必须可溯源
3. 避免空泛营销语
4. 统一正式入口，减少读者决策成本
5. 先保留已有有效信息，再增量补足缺失结构

### README 首屏增强

吸收 `zh-readme` 的首页方法，首屏至少回答三个问题：

1. **这是什么**：一句话价值主张，明确项目解决什么问题
2. **适合谁**：点名目标用户或典型场景
3. **怎么开始**：给出最短安装或运行方式

可验证时再追加：

1. License / Version / Build 状态 badge
2. 官网、文档站、Issue、下载入口等统一正式入口
3. Star、代表性案例、更新时间等社交证明

不可验证时必须省略，不允许脑补。

### 可选内容

以下内容只有在仓库内或可验证元数据中能确认时才允许展示，否则省略：

1. Star / Version / License badge
2. 代表性案例
3. 更新时间类社交证明

### README 推荐结构

1. 项目名称
2. 一句话价值主张
3. 项目亮点
4. 安装
5. 快速开始
6. 使用示例
7. 项目结构
8. 适用场景
9. 配置
10. 开发
11. 贡献
12. License

### README 与 Diataxis 的分工

虽然本技能不额外生成 tutorial / how-to / reference / explanation 四类文件，但 README 需要承担其中两类入口职责：

1. **tutorial 入口**：用最短路径让新读者先跑起来
2. **how-to 入口**：给出常见使用路径和下一步文档跳转

不要把完整 reference 和架构解释全塞进 README；这部分应链接到 `docs/project-map.md` 或 `docs/architecture.md`。

### 自检清单

1. 首句是否讲清解决的问题
2. 是否给出最短可运行示例
3. 是否覆盖安装、使用、贡献、License
4. 是否避免 AI 腔与空泛文案
5. 命令是否可复制执行
6. 信息不足时是否明确标记“待补充”而非编造
7. README / 官网 / 贡献入口 / 下载入口是否口径一致
8. 是否把本应放在 architecture 或 project-map 的内容错误塞进首页
