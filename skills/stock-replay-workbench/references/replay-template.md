# Replay Template

## 适用场景

日内复盘、盘后总结、主线梳理、题材回顾、明日观察清单。

## 写作要求

1. 先给市场结论，再展示证据。
2. 主线必须落到可验证的板块和个股，不要只写空泛主题。
3. 对每个判断尽量绑定事实依据，例如涨停池、成交额、资金流、公告、龙虎榜。
4. 明日观察点应是可验证条件，不是情绪化预测。
5. 如果某一块数据来自 best-effort 能力，在对应段落或结尾保留 warning。
6. 完成内容组织后，主动将生成的 Markdown 内容写入到当前工作区根目录的 `./.analysis/YYYY-MM-DD-xxx.md` 文件中；如果 `.analysis/` 不存在，先创建再写入。
7. 如果已拿到行业 / 概念资金流，优先放入 `### 板块资金流`，不要只散落在文字段落里。
8. 如果已拿到重点股 `fundamental` 扩展字段，优先放入 `### 重点标的基本面`，避免只在正文里零散提及。
9. 如果已拿到 `event_snapshots.market` 或 `event_snapshots.focus`，优先单列 `### 事件快照` 和 `### 重点股事件催化`，再在 `### 资金与事件` 中保留更高层的总结。

## 推荐能力组合

盘后复盘通常至少调用这几个能力模块：

1. 市场宽度与情绪
2. 榜单与活跃度
3. 板块与题材
4. 资金与博弈
5. 公告与催化（如当天确有关键事件）

## 单票深挖追加模板

如果复盘里需要对个股做单独拆解，追加这段：

```markdown
### {股票名}({代码})

- 现价/涨跌幅: ...
- 所属题材: ...
- 今日强弱原因: ...
- 资金面: ...
- 事件面: ...
- 角色定位: 龙头 / 中军 / 补涨 / 跟风 / 反抽
- 明日看点: ...
- 风险: ...
```

## 禁止事项

不要在复盘中直接给出收益承诺、确定性买卖点或保证性结论。
