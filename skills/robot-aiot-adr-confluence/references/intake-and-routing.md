# Phase 0: 信息评估与路由

先判断用户要的是“先成文”还是“直接发布”。这一步决定后续哪些信息是阻塞项，哪些可以先用 `[待补充]` 占位。

## 最低输入要求

### 仅生成文档时

至少收敛以下信息：

1. 核心问题或业务痛点
2. 作者或团队名称
3. 文档标题或主题方向

以下信息可缺省为 `[待补充]`：

1. 候选方案
2. 最终选定方案
3. 状态
4. 编号
5. 评审人

### 生成并发布到 Confluence 时

除文档内容外，还必须具备：

1. 文档标题
2. 父页面 ID 或页面 ID
3. 发布目标空间或页面归属信息（若 CLI 需要）

## 模板相关的附加要求

1. ADR 标准：发布前应有最终选定方案，且候选方案至少能形成有效对比；若用户要求“先起草”，可先用 `[待补充]` 占位，但不能宣称已完成定稿
2. 技术提案：允许在方案尚未最终拍板时先生成提案草稿，候选方案和推荐方案可并存
3. 简报：必须有推荐方案、主要风险和决策需求，否则只能输出草稿

## 路由规则

1. 信息充分：直接进入文档生成
2. 需求太粗：先做需求收敛
3. 候选方案很多但取舍不清：先做方案发散
4. 关键事实可从代码、配置或环境中获取：优先自行查找，不向用户重复索取
5. 用户明确说“直接生成”：跳过追问，但缺口必须显式标记为 `[待补充]`
