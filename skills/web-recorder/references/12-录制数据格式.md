## 大响应体优化机制

为减少 `recording.json` 体积，录制器会自动优化 >60KB 的响应体。

### 规则一：数组截断

**触发条件（同时满足）：**
- 响应体 > 60KB
- 数组元素 > 20 行

**截断规则：**
- 保留头尾各 3 个元素（共 6 个）
- 每个元素内部结构完整保留（所有字段）
- 外层 JSON 结构完整保留（所有嵌套对象、非数组字段）

**截断标记：**
被截断的响应体会包含 `arrayTruncated` 字段：
```json
{
  "requestId": "req_0011",
  "body": "{...截断后的body...}",
  "arrayTruncated": [
    {
      "path": "data.list",
      "originalCount": 164,
      "keptCount": 6
    }
  ]
}
```

**字段说明：**
- `path`: 被截断的数组路径（如 `data.list` = 列表数据）
- `originalCount`: 原始元素数量（AI 用于判断数据规模）
- `keptCount`: 保留的元素数量（头尾各3个）

---

### 规则二：JSON 字符串摘要

**触发条件（同时满足）：**
- 响应体 > 60KB
- 字符串长度 > 5KB

**规则：**
- 尝试解析为 JSON
- 解析成功 → 转为摘要对象
- 解析失败 → 保持原样（不截断）

**摘要对象格式：**
```json
{
  "componentContent": {
    "_summary": "JSON字符串(70000字符)，解析后包含19个字段",
    "_keys": {
      "tileLayout": "76B, Object{8}",
      "refThemeAttr": "2.8KB, Object{49}",
      "attribute": "66.5KB, Object{21}",
      "id": "string",
      "type": "string"
    },
    "_preview": "{\"tileLayout\":{\"w\":12,\"h\":51,..."
  },
  "stringSummarized": [
    {
      "path": "data.components[0].componentContent",
      "originalSize": 71680,
      "keyCount": 19
    }
  ]
}
```

**字段说明：**
- `_summary`: 描述信息（原始大小、字段数量）
- `_keys`: 每个字段的名称、大小、类型
- `_preview`: 前 200 字符预览
- `stringSummarized`: 被摘要的字符串信息列表

## 需要完整数据时

从 `recording-bodies.jsonl` 读取完整响应体：
```powershell
# 按 requestId 查找完整响应体
$line = Get-Content recording-bodies.jsonl | Where-Object { $_ -match '"requestId":"req_0011"' }
$json = $line | ConvertFrom-Json
$fullBody = $json.body | ConvertFrom-Json
```
