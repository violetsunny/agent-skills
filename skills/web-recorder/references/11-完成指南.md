## 三、网站交互经验库更新

### 3.1 更新时机

**必须在用户确认脚本 OK 后才更新。**

流程：展示完成信息 → 询问"脚本是否 OK？" → 用户确认 OK → 更新经验库

### 3.2 更新步骤

1. **检查经验库**：`references/site-experience/` 目录
2. **判断策略**：

| 情况 | 操作 |
|------|------|
| 没有当前域名的经验文件 | 创建新文件 |
| 有经验，新功能模块 | 追加验证记录 |
| 有经验，新交互方式 | 追加到对应章节 |
| 有经验，旧经验有误 | 修正并标注日期 |

### 3.3 应该记录的内容

- ✅ 鉴权方式（认证类型、登录检测逻辑）
- ✅ 接口交互模式（异步任务/直接下载/前端生成）
- ✅ 页面结构特征（SPA/通用选择器）
- ✅ 下载触发方式

### 3.4 不该记录的内容

| 禁止记录 | 原因 |
|---------|------|
| ❌ 具体的事业部编码 | 不同事业部不同 |
| ❌ 具体的状态码映射 | 不同业务场景不同 |
| ❌ 具体的 API 路径 | 每个功能模块不同 |
| ❌ 具体的参数字段名 | 每个导出功能不同 |
| ❌ 具体的文件命名规则 | 业务需求决定 |

**判断标准：** 如果这个信息在下次录制同系统的不同功能时可能会变，就不要记录。

### 3.5 经验文件命名

格式：`<系统名>-<入口域名>.md`

- ✅ `SRM-gsrm.midea.com.md`（入口域名）
- ❌ `SRM-webedit.midea.com.md`（API 域名，不要用）
