## 二、三种模式

### 模式A：接口直调（推荐 ✅）

**原理：** 直接调用后端 API，不操作页面元素

**流程：**
```
登录拿 Token → 按链路顺序调接口 → 动态生成参数 → 保存结果
```

**适用条件：**
- ✅ 无强环境校验（不检测 WebDriver、不校验 Canvas 指纹）
- ✅ 加密可复现（能在 Node.js 中生成 sign/token）
- ✅ 所有参数来源已搞清楚

**优点：** 稳定、快速、不受页面改版影响
**缺点：** 遇到强混淆/环境校验就搞不定

### 模式B：页面模拟操作（DOM 回放）

**原理：** 保留浏览器会话，模拟用户点击/输入

**流程：**
```
保留浏览器会话 → 导航到页面 → 模拟点击/输入 → 等待结果
```

**适用条件：**
- ⚠️ 强混淆/环境校验（接口参数看不懂、生成逻辑找不到）
- ⚠️ WebSocket 实时通信（数据通过 WS 推送）
- ⚠️ 接口直调两轮深入分析都搞不定

**优点：** 能应对复杂场景
**缺点：** 慢、不稳定、选择器可能失效

### 模式C：混合模式（复杂页面首选 ⭐）

**原理：** 核心接口直调 + 特殊校验步骤页面模拟

**流程：**
```
登录 → API 调大部分接口 → 遇到校验时模拟页面操作 → 继续 API
```

**适用场景：**
- 大部分接口可以直调，但某一步需要页面操作（如验证码、滑块）
- 数据获取用 API，文件下载用页面模拟

```
开始

  │

  │                   │
  │                   └── 不能 → ✅ 模式C：混合模式
  │                              （加密步骤用页面模拟）
  │
  └── 否 → 经过两轮深入分析了吗？（见下方）
            │

            │
            └── 还没有 → 执行两轮深入分析
```

## 四、三轮深入分析（API 模式优先 · 强制）

> ⚠️ **铁律2**：必须经过三轮深入分析都不行，才能咨询用户是否转UI。
> 
> ⚠️ **第三轮必须重新分析二次录制数据**，不能跳过。

### 第一轮：扩大范围

1. 检查所有请求（包括 GET、OPTIONS、iframe 内的请求）
2. 分析前端代码（从 Network 请求中找 API endpoint 模式）
3. 检查数据源（页面数据从哪来？导出按钮触发了什么请求？）
4. 尝试构建调用链（即使参数不完整，先画出可能的流程）

### 第二轮：换角度

1. 重新审视录制数据（有没有遗漏的请求？被误判为"非业务"的？）
2. 检查认证问题（是否因为 header 缺失导致调用失败？）
3. 检查页面交互（是否需要先 hover/click 才触发 API？）
4. 查阅经验库（同系统的其他功能有没有可复用的？）

### 第三轮：重新分析二次录制数据（强制！）

> ⚠️ **这一轮不能跳过！** 必须重新打开二次录制的 recording.json，做全面分析。

1. **重新打开** `analysis/comparison/recording.json`
2. **逐请求检查**：有没有第一轮/第二轮遗漏的请求？
3. **对比两次录制的差异**：是否有某个请求只在第二次出现？
4. **检查响应体**：是否有之前忽略的关键字段？
5. **重新验证调用链**：之前的链路假设是否正确？

### 三轮都不行 → 填写"API失败证据表"

**必须填写以下表格，才能咨询用户是否转UI：**

```markdown
## API失败证据表

### 第一轮尝试（扩大范围）
| 尝试内容 | 结果 | 为什么失败 |
|---------|------|-----------|
| 检查所有请求 | 没找到导出API | 导出是前端JS生成 |
| ... | ... | ... |

### 第二轮尝试（换角度）
| 尝试内容 | 结果 | 为什么失败 |
|---------|------|-----------|
| 检查前端代码 | 没找到可复现的逻辑 | 使用了JSZip |
| ... | ... | ... |

### 第三轮尝试（重新分析二次录制数据）
| 尝试内容 | 结果 | 为什么失败 |
|---------|------|-----------|
| 重新检查 analysis/comparison/recording.json | 确认无后端导出API | 两次录制都只有前端生成 |
| ... | ... | ... |

### 结论
经过三轮深入分析，API模式无法实现，原因：xxx
建议转UI模式。是否同意？
```

### 向用户咨询（必须等证据表填完）

```
"经过三轮深入分析（见上方证据表），API模式无法实现。

主要原因：
1. xxx
2. xxx
3. xxx

建议方案：
A. 重新录制（可能录制时间不够长/操作不完整）
B. 使用UI模式（Playwright 自动化，模拟用户操作）

你选择哪个？"
```

**禁止行为：**
- ❌ 没有深入分析就直接说"只能用UI模式"
- ❌ 只分析一轮或两轮就放弃
- ❌ 看到动态参数就放弃API模式
- ❌ **跳过第三轮（重新分析二次录制数据）**
- ❌ **不填证据表就咨询用户**

**违反后果：** 未经三轮分析就转UI = AI责任
