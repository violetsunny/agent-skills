# 中断恢复指南

> 当你从错误/中断/会话重置中恢复时，必须执行以下步骤

---

## 🔒 铁律提醒

> **铁律5：中断后必须恢复检查点**
> 
> 中断恢复后，必须先读取最近的存档文件，确认当前阶段，重述铁律，才能继续。

---

## 一、什么时候需要执行恢复？

| 场景 | 触发条件 |
|------|---------|
| 脚本报错 | 测试阶段脚本运行失败 |
| 会话中断 | 用户说"继续"或"接着做" |
| 上下文丢失 | 不确定当前在哪个阶段 |
| 模型重置 | 新会话开始，需要继续之前的任务 |

---

## 二、恢复步骤（强制）

### Step 1：读取最近的存档文件

```
检查顺序：
1. analysis/step5-mode-decision.md → 如果存在，说明已完成阶段七
2. analysis/step4-comparison.md → 如果存在，说明已完成阶段六
3. analysis/step3-api-breakdown.md → 如果存在，说明已完成阶段五
4. analysis/step2-chain-analysis.md → 如果存在，说明已完成阶段四
5. analysis/step1-traffic-classify.md → 如果存在，说明已完成阶段三
6. recording.json → 如果存在，说明已完成阶段一
```

### Step 2：确认当前阶段

根据存档文件存在情况，确定：
- **已完成的最后阶段**：有存档文件的最大阶段号
- **下一步应该做的阶段**：最后阶段 + 1

### Step 3：重述铁律

在对话中明确输出：

```
🔒 铁律提醒：
1. 不得跳过任何阶段 — 当前从阶段X继续
2. API模式优先 — 必须三轮分析才能考虑转UI
3. 二次录制是必经阶段 — 如未完成阶段六，必须补做
4. 请求体用模板替换法 — 不得凭理解重构
5. 中断后必须恢复检查点 — 已完成
```

### Step 4：向用户确认

```
"我从阶段X继续，下一步是阶段Y。OK？"
```

等待用户确认后，再继续执行。

---

## 三、阶段完成确认模板

每个阶段结束时，必须输出以下格式的确认：

```
✅ 阶段X完成
- 产出文件：xxx
- 关键结论：xxx（一句话总结）
- 下一步：阶段Y
- 当前状态：[继续/等待用户]
```

**示例：**

```
✅ 阶段五完成
- 产出文件：analysis/step3-api-breakdown.md
- 关键结论：3个核心API，2个等级1参数，1个等级2参数
- 下一步：阶段六（二次录制）
- 当前状态：继续
```

## 五、常见恢复场景

### 场景1：测试失败后恢复

```
1. 读取 run-api.ts，确认脚本版本
2. 读取错误日志，确认失败原因
3. 判断：是脚本问题还是分析遗漏？
   - 脚本问题 → 修改脚本，重新测试（阶段十内）
   - 分析遗漏 → 回退到对应阶段，补充分析
4. 输出恢复确认
```

### 场景2：会话中断后恢复

```
1. 读取最近的存档文件
2. 确认当前阶段
3. 重述铁律
4. 向用户确认继续
```

### 场景3：用户说"刚才说到哪了"

```
1. 读取所有存档文件
2. 列出已完成的阶段
3. 告知用户当前进度
4. 询问是否继续
```

---

## 六、禁止行为

- ❌ 不读存档就直接继续（可能跳过阶段）
- ❌ 凭记忆判断当前阶段（记忆可能出错）
- ❌ 不重述铁律就继续（容易遗忘规则）
- ❌ 不向用户确认就继续（用户可能已改变需求）

---

## 七、下一步

恢复完成后，按正常流程继续执行下一阶段。
