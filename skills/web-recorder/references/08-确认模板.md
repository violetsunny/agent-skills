# 阶段八：确认

> 把分析结果给用户做最终确认，避免生成错误脚本

---

## 一、目标

让用户确认 AI 理解正确。用户只需要确认"你理解我要做什么了吗？"，不需要确认技术细节。

---

## 二、展示模板（强制格式）

```
📋 我理解你要做的是 — <任务名称>

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🔄 操作流程

1. 登录 SRM 系统
2. 进入"供应商管理" → "批准供应商列表"
3. 选择"家用事业部"
4. 点击导出
5. 等待下载完成

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📥 下载关联机制（如有下载）

export API → 后端生成文件
    ↓
轮询系统消息 → 获取文件名
    ↓
download API → 下载文件

关联字段：消息的 downloadUrl
过滤条件：title="采购计划Excel数据导出" + 最新一条

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📌 关键规则

- 默认选择"家用事业部"
- 只导出"已禁用"状态的数据
- 导出的文件保存到桌面

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 是这样吗？有没有需要修改的地方？
```

---

## 三、禁止行为

- ❌ 用自己的话概括，不按模板格式
- ❌ 省略分隔线和模块标题
- ❌ 只展示技术细节，不展示业务流程
- ❌ 用户未确认前，禁止进入下一阶段

---

## 四、用户反馈处理

| 用户说 | 处理方式 |
|--------|----------|
| "对的" / "没错" | 更新 task-meta.json，进入阶段九 |
| "不对，应该是..." | 修正理解，重新确认 |
| "不确定" / "先这样吧" | 记录为"待验证"，进入阶段九，测试时验证 |

---

## 五、输出

更新后的 `task-meta.json`（最终版），进入阶段九生成脚本。
