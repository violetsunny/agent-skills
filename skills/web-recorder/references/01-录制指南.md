## 〇、环境检查（强制前置）

**每次执行录制前，必须先运行环境检查脚本：**

```bash
cd <skill-dir>
node scripts/check-env.js
```

**检查项：**
1. Node.js 版本（>= 18）
2. npm 依赖是否完整（缺失则自动 `npm install`）
3. Chrome 浏览器是否存在

**退出码：**
- `0` = 全部通过，可以继续
- `1` = 有缺失且无法自动修复，需要手动处理

> ⚠️ **如果环境检查失败，不得跳过，必须修复后才能继续。**

#### ⚠️ 环境检查后：确认无多余浏览器

- 如果之前用 `browser start` 启动过浏览器，必须先 `browser stop` 关掉
- 录制器会自己启动浏览器，不需要预先启动
- 多个浏览器窗口会导致冲突

## 一、录制器已自动过滤的内容

录制器（record.ts）在录制时已自动做了大量过滤工作，以下数据**不会**出现在 recording.json 中：

- **静态资源**：图片、CSS、字体、JS 文件等（resourceType 为 image/css/font/script 的请求）
- **路过式 hover**：hoverDuration < 1s 且无关联 API 的 mouseenter 事件
- **无业务意义的 focus/blur**：不触发 API 的聚焦/失焦
- **连续 scroll**：同一目标间隔 < 1s 的连续滚动只保留最后一次
- **浏览器标准 headers**：accept、sec-*、user-agent 等（保留所有非标准 headers）

> 💡 这意味着你拿到的录制数据已经是"干净"的业务流量，不需要再手动过滤静态资源。

### 2.3 启动录制器

> ⚠️ **前置条件：用户已回复【开始】，才能执行以下步骤！**

```bash
cd <skill-dir>

# 新录制（自动添加时间戳 YYYYMMDD_HHMM）
npx ts-node scripts/record.ts --name "my-task" --app-url "https://app.example.com"

# 复用已有文件夹（二次录制时用）
npx ts-node scripts/record.ts --name "my-task" --app-url "https://app.example.com" --reuse "my-task_20260604_1546"

# 指定输出目录
npx ts-node scripts/record.ts --name "my-task" --app-url "https://app.example.com" --output "D:\tasks"
```

**运行方式：** PTY 模式（`pty: true, background: true`）

> ⚠️ 统一用 `--app-url`，不要根据 URL 判断从哪开始录。如果需要登录，登录操作也会被录下来。

#### ⚠️ 重要：不要先 `browser start`！

- 录制器用 `chromium.launch()` 启动独立浏览器，不是连接已有浏览器
- 如果先 `browser start`，会导致两个浏览器窗口冲突
- **正确流程：** 环境检查 → 直接启动录制器 → 录制器自动开浏览器

#### ⚠️ 重要：不要设 timeout！

- 录制时长取决于用户操作速度，可能超过几分钟
- 设了 timeout 会导致超时后录制器被强制终止，录制数据丢失
- **正确做法：** 用 `background: true` 让录制器一直运行，直到 `.done` 文件触发保存

```javascript
// ✅ 正确
exec({
  command: "npx ts-node scripts/record.ts ...",
  pty: true,
  background: true,
  yieldMs: 20000
  // 不设 timeout
})

// ❌ 错误
exec({
  command: "npx ts-node scripts/record.ts ...",
  pty: true,
  background: true,
  timeout: 60  // 会导致超时终止
})
```

### 2.4 结束录制

用户在对话框告诉 AI "录完了" → AI 创建 `.done` 文件 → 录制器检测到后自动保存退出。

#### ⚠️ `.done` 文件路径规则（强制！）

**录制器的实际输出目录 = `--output` 参数 + 自动生成的 `任务名_时间戳` 子目录**

AI **无法提前知道**这个子目录的精确时间戳，**必须从录制器启动输出中读取**。

#### 获取 `.done` 路径的标准流程（不可跳过！）

```
Step 1: 启动录制器（PTY模式，background，yieldMs=15000）
        ↓
Step 2: 【必须执行】立即 poll 录制器输出（timeout=10000）
        ↓
Step 3: 【必须执行】从输出中找到包含 "Output  :" 的行
        注意：输出可能有 ANSI 转义码（如 [25l、[K 等），忽略这些转义码
        示例输出行：Output  : D:\Users\xubx4\.openclaw\rpa\tasks\任务名_20260610_1411
        ↓
Step 4: 【必须执行】提取 "Output  : " 后面的完整路径，记为 DONE_DIR
        提取方法：找到 "Output  : " 后，取到行尾（或下一个转义码前）
        ↓
Step 5: 【必须记住】把 DONE_DIR 保存在变量或注释中，等用户说"录完了"时使用
        ↓
Step 6: 用户说"录完了"时，创建文件：
        New-Item -Path "<DONE_DIR>\.done" -ItemType File -Force
```

**⚠️ 禁止行为：**
- ❌ 不 poll 输出，自己猜测路径
- ❌ 用 `--output` 参数值代替实际路径（会少一层时间戳目录）
- ❌ 自己拼接时间戳（可能差1分钟导致路径错误）
- ❌ poll 输出后不提取路径，等用户说"录完了"才去翻输出（可能已经忘了）

**✅ 正确做法：**
- ✅ 每次启动录制器后，必须立即 poll 输出并提取 `Output  :` 后面的路径
- ✅ 把提取的路径保存为变量（或在对话中明确记录），用户说"录完了"时直接使用
- ✅ 如果 poll 输出中没有找到 `Output  :`，说明录制器启动失败，需要检查错误信息

**🔍 提取路径示例：**
```
原始输出（含 ANSI 转义码）：
[25l    Task    : 小龙虾使用情况导出[49X
    Output  : D:\Users\xubx4\.openclaw\rpa\tasks\小龙虾使用情况导出_20260610_1411[6;1H[?25h

提取后：
DONE_DIR = "D:\Users\xubx4\.openclaw\rpa\tasks\小龙虾使用情况导出_20260610_1411"
```

#### 示例

**新录制：**
```
# 启动命令（不指定 --output，使用默认目录）
npx ts-node scripts/record.ts --name "my-task" --app-url "https://..."

# 录制器输出
    Output  : D:\Users\xubx4\.openclaw\rpa\tasks\my-task_20260610_1411

# ✅ .done 路径
New-Item -Path "D:\Users\xubx4\.openclaw\rpa\tasks\my-task_20260610_1411\.done" -ItemType File -Force
```

**二次录制（--output 指向子目录）：**
```
# 启动命令
npx ts-node scripts/record.ts --name "my-task" --app-url "https://..." --output "D:\...\my-task_20260610_1411\analysis\comparison"

# 录制器输出（注意：多了一层 my-task_20260610_1419）
    Output  : D:\...\my-task_20260610_1411\analysis\comparison\my-task_20260610_1419

# ✅ .done 路径（必须包含最后那层时间戳目录）
New-Item -Path "D:\...\my-task_20260610_1411\analysis\comparison\my-task_20260610_1419\.done" -ItemType File -Force

# ❌ 错误（少了最后一层时间戳目录）
New-Item -Path "D:\...\my-task_20260610_1411\analysis\comparison\.done"
```

#### 常见错误

| 错误 | 原因 | 后果 |
|------|------|------|
| `.done` 放在 `--output` 指定的目录 | 忽略了录制器自动追加的 `任务名_时间戳` 子目录 | 录制器检测不到 `.done`，无法停止 |
| 自己拼接时间戳 | 时间戳精确到分钟，可能差1分钟导致路径不对 | 同上 |
| 不 poll 录制器输出 | 不知道实际路径 | 只能猜，容易猜错 |

## 四、输出文件

| 输出文件 | 说明 |
|----------|------|
| `recording.json` | 完整录制数据（精简版，~300KB） |
| `recording-bodies.jsonl` | 所有响应体的完整版（JSONL 格式，用于补充分析） |
| `api-list.md` | 接口清单（所有业务API列表，阶段三直接读取） |
| `downloaded-files/` | 录制时实时保存的下载文件（含表头提取） |

### 4.1 downloaded-files/ 目录

- 每个下载事件触发时，立即 `saveAs()` 保存文件
- 文件命名：`01_原始文件名.xlsx`（序号防覆盖）
- 自动提取表头（xlsx/csv），存入 `recording.json` 的 `downloadedFiles[].headers`
- 每个文件关联触发它的 API 请求（`downloadedFiles[].relatedRequestIds`）

### 4.2 数据精简策略

recording.json 保存时自动过滤无用数据（从 ~4MB 降到 ~300KB）：

- **Response Body**：默认只保存摘要（bodySummary），白名单 API（含 export/create/generate/submit/download/dictionary/enum）保存完整 body
- **Request Headers**：排除浏览器标准 headers，保留所有非标准 headers（可能是认证相关的）
- **完整模式**：`--save-full` 参数可保存完整数据

## 六、选择器实时验证

录制器自动验证每个选择器：

1. **唯一性检查** — `querySelectorAll(selector).length === 1`
2. **稳定性评级** — S/A/B/C/D 五级
3. **选择器策略** — 记录使选择器唯一的策略（selectorStrategy 字段）
4. **操作-API 关联** — 匹配点击操作与 2 秒内的 POST/PUT/PATCH 请求
