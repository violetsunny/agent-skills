# 阶段二：追问

> 趁用户记忆新鲜，追问业务逻辑和隐性规则

---

## 一、追问原则

### 核心原则：能自己查到的不问用户

| 类型 | 处理方式 | 示例 |
|------|----------|------|
| **业务规则** | ✅ 问用户 | 默认筛选条件、循环逻辑、异常处理 |
| **技术参数** | ❌ 不问，自己查录制记录 | 参数编码、API路径、字段名 |
| **输出格式** | ❌ 不问，直接解析录制记录 | CSV/Excel/PDF |
| **文件命名** | ✅ 问，但提供推荐选项 | 见下方模板 |

### 禁止追问的内容

- **参数编码**：用户说"事业部默认选家用" → 自己从录制记录匹配 buCode="100909"
- **文件格式**：直接从 API 响应头/下载链接后缀解析
- **文件命名**：提供三个选项让用户选（系统默认/推荐命名/自定义）

## 二、追问模板

```
📋 我需要确认几个问题 — <任务名称>

刚才的录制已完成，我了解了你的操作流程。为了让脚本更贴合你的实际使用场景，
请帮我补充以下信息：

🔧 1. 每次都要填的内容
   - 这个操作每次都要选什么？有没有每次都一样的默认值？

🔄 2. 每次都要改的内容
   - 哪些是每次运行时需要改的？（比如：日期、金额、原因）

📂 3. 导出的文件放哪里？
   - 默认放在桌面，需要改到其他位置吗？

📄 4. 文件叫什么名字？
   A) 系统默认命名
   B) 推荐命名：<任务类型>_<参数标识>_<YYYYMMDD_HHMM>.<格式>
   C) 自定义命名

🔄 5. 需要批量处理吗？
   - 需要循环执行吗？数据从哪来？

📋 6. 有什么特殊规则？

⚠️ 7. 遇到错误怎么办？

🔮 8. 有没有"等待"的环节？
   - 点了某个按钮后，要不要等系统处理？
   - 有没有"如果XX就YY"的情况？

请逐项回答，不确定的可以先跳过。
```

---

## 三、追问技巧

| 任务类型 | 重点追问 |
|----------|----------|
| 查询/导出 | 默认筛选条件、文件命名规范、空数据处理 |
| 提交 | 动态字段、必填/可选、校验规则、提交后确认 |
| 批量处理 | 循环数据源、停止条件、失败重试、进度通知 |

- 用户说"不确定" → 记录为"待确认"，在确认阶段再次提出
- 如果用户不耐烦，分批问：第一轮问必问的（默认参数+动态参数+输出+命名），第二轮问可选的
