# AGENTS.md — agent-skills repository

Content repository (Markdown), not a code project. No build system, no test runner, no root `package.json`, no `WorkSpace.json`, no CI. Contains 688 external skill copies + 17 user-authored skills + 20 agents + 20 root commands + 12 opsx commands + language-specific rules. `skills-lock.json` tracks midea marketplace skill lock versions (currently only `i-have-adhd`).

## Directory boundaries — critical

- `self-skills/` — **user's original work, the only true source**. May freely modify. Each skill has `SKILL.md` + optional `references/`, `scripts/`, `modules/`. 12 of 17 use `robot-aiot-*` prefix; 5 use other names (`dev-paradigm-matt`, `easy-crawler`, `mac-safe-storage-cleaner`, `opsx-workflow-hooks`, `stock-replay-workbench`).
- `skills/` — **external skill copies, read-only**. Never modify directly; updates arrive only via the sync skill. 688 skill dirs + 4 meta-dirs: `generated/` (multi-agent pack exports), `in-progress/` (beta), `misc/` (rarely-used), `deprecated/` (contains only README.md; retired skills are deleted).
- `agents/` — agent markdown files (reviewer/build-resolver personas).
- `commands/` — slash command definitions; `commands/opsx/` is OpenSpec-generated (managed by module 2 of sync skill).
- `rules/` — coding rules by language (`common/`, `java/`, `react/`, `typescript/`, `vue/`).
- `template/SKILL.md` — minimal template for new skills.
- `docs/skills-overview.md` — auto-generated skill catalog (do not hand-edit; regenerated by sync skill module 5). `docs/skills-verification-checklist.md` — multi-round verification reference for the 5 presentation/diagram skills.
- `key-skills-git/` — **1.9 GB of local git clones** of external skill source repos (18 projects). Untracked, not in `.gitignore`. Never `git add`, commit, or modify — these are read-only reference clones used by sync skill module 3.1 as rsync fallback when npx update fails.
- `openspec/` — OpenSpec spec-driven change tracking (`config.yaml`, `changes/`, `specs/`).
- `spec/agent-skills-spec.md` — points to external spec at `https://agentskills.io/specification`.
- `.agents/memories/MEMORY.md` — user feedback rules (provenance bans, required deps, validation artifact placement). Read before editing self-skills.

## Sync mechanism

`self-skills/robot-aiot-self-skill-sync` is the operational core. It syncs between three locations:
1. `~/.agents/skills/` (runtime, deployed)
2. `self-skills/` (true source for user-authored skills)
3. `skills/` (knowledge-base copies of external skills)

Key rules:
- **Never `--delete`** in any sync direction. Only add/overwrite.
- `skills/` is never git-pulled (marked `[SKIP-NOSYNC]`); updates come via npx/rsync from external sources.
- `self-skills/ ↔ ~/.agents/skills/` is bidirectional file-level sync (newer wins by mtime; skill-level only updates, never adds new skills to runtime).
- `skills/_lifecycle.json` tracks usage stats and patch hints per skill.
- `_mideameta.json` in runtime skills is always authoritative — never compare, deploy, or write back it.
- After modifying `self-skills/`, the sync skill deploys to `~/.agents/skills/` — do not manually copy.

## Git constraints

- Branch: `main`. Remote: `github.com/violetsunny/agent-skills.git`
- **Push is prohibited** — local commits only, unless user explicitly requests push.
- `key-skills-git/` is untracked and NOT in `.gitignore` — always exclude it from `git add` (use `git add` with explicit paths, never `git add .`).
- Commit messages: `FEAT:/FIX:/CHORE:` prefix + `JIRA: main DIFF:` summary line (e.g. `FEAT: 描述 JIRA: main DIFF: 变更摘要`). Plain `update skills` also appears in history for sync-only batch updates.

## Editing skills in this repo

- Use `template/SKILL.md` as the starting point for new skills.
- SKILL.md frontmatter: `name` + `description` fields are required.
- User-authored skills under `self-skills/` predominantly follow the `robot-aiot-*` naming convention (12 of 17).
- SKILL.md must not contain provenance lines ("拆分而来", "融合而成", etc.) — describe current capabilities only.
- `archify`, `diagram-design`, `ui-ux-pro-max` are **required runtime dependencies** for diagram/presentation skills; dependency tables must mark them required, never "optional" or "fallback to built-in".
- Python scripts in `self-skills/*/scripts/` use standard library only unless a `requirements.txt` exists in that skill.
- Validation artifacts (test decks, screenshots, measurement reports) go in the delivery project's `test-run/<batch>/`, not in this repo or `/tmp`. `/tmp` only for process-temporary files. Do not clean before user confirms.
