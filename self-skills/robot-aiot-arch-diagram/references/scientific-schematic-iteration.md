# AI 生成出版级示意图迭代流程

## 1. 定位与边界

用图像模型生成出版级科学/技术示意图——神经网络架构、系统框图、方法论流程图（CONSORT/PRISMA 类）、生物通路、电路示意、网络拓扑、概念框架——并以「生成 → 质量审查 → 低于阈值定向重生成」的迭代循环保证产出达到目标文档类型的质量线。典型工具组合：图像生成模型（如 Nano Banana 2）+ 视觉审查模型（如 Gemini Flash 系列），可经 OpenRouter 等网关调用；具体模型按环境配置解析。

与风格化 AI 生图能力的分工：

- 封面/Banner/视觉隐喻类规则：产出设计感视觉，prompt 不含文字，不承载事实信息。
- 本流程：产出带标签、带数据、承载事实的示意图，必须通过质量审查与人工校验后才能使用。
- 程序化 SVG/draw.io 图表仍是技术真源首选；本流程用于程序化渲染无法满足视觉品质的出版/插图场景，或用户明确要求 AI 生成示意图时。

能力硬边界（决定要不要走本流程）：

1. 输出仅为栅格 PNG——无矢量路径、无 DPI 控制参数，分辨率由图像模型决定。
2. 仅 RGB 色彩空间；CMYK 印刷需下游转换。
3. 线宽与字号只能在 prompt 中描述，结果必须目检确认。
4. 期刊要求 PDF/EPS/矢量或 300dpi TIFF 时，生成后做下游格式转换，并按最终印刷尺寸检查效果。

数据安全：prompt 与生成图像会发送到外部 API，受网关与模型提供商数据政策约束。禁止在 prompt 中写入未发表数据、患者信息、保密期内容。

## 2. 迭代循环

```
1. 图像生成模型按 prompt 产出 v1
2. 视觉审查模型按五维评分（§4）打分
3. score ≥ 文档类型阈值（§3）？
     是 → 结束（early stop，不再多花一次调用）
     否 → 从 critique 提取具体问题，定向改进 prompt（§6），回到 1
4. 重复直到达标或触及迭代上限
```

- 迭代上限：2 轮。触顶后保留最后一张图并如实报告其真实分数，禁止为达标虚报分数。
- 每轮迭代 = 2 次 API 调用（1 次生成 + 1 次审查）；首轮即达标时总成本就是 2 次调用。
- 产物：版本化文件 `name_v1.png`、`name_v2.png`，胜出图在用户指定路径留一份副本，以及 `name_review_log.json`（§7）。

## 3. 文档类型 → 质量阈值

| 文档类型 | 阈值 | 说明 |
|---|---|---|
| journal | 8.5/10 | Nature、Science 等同行评审期刊 |
| conference | 8.0/10 | 会议论文 |
| thesis | 8.0/10 | 学位论文 |
| grant | 8.0/10 | 基金申请书 |
| preprint | 7.5/10 | arXiv、bioRxiv 等预印本 |
| report | 7.5/10 | 技术报告 |
| poster | 7.0/10 | 学术海报 |
| presentation | 6.5/10 | 幻灯片、口头报告 |
| 默认 | 7.5/10 | 未指定文档类型时 |

阈值而非分数本身决定是否继续迭代：同一张 7.5 分的图，对 poster（7.0）直接通过，对 journal（8.5）必须继续改进。文档类型未指明时按默认阈值执行，并在交付时说明所用阈值。

## 4. 质量审查评分标准

审查模型对五个维度各打 0-2 分，总分 10：

1. **科学准确性** — 概念、记号、关系正确，无虚构成分
2. **清晰度与可读性** — 易于理解，视觉层次清楚
3. **标签质量** — 完整、可读、风格一致
4. **布局与构图** — 流向合逻辑、均衡、无重叠
5. **专业外观** — 达到出版级质感

审查输出固定格式：

```
SCORE: 8.0

STRENGTHS:
- Clear flow from top to bottom
- All phases properly labeled

ISSUES:
- Participant counts slightly small
- Minor overlap on exclusion box

VERDICT: ACCEPTABLE (for poster, threshold 7.0)
```

判定规则：score ≥ 阈值 → 停止；score < 阈值 → 进入 §6 定向重生成。

**score 解析防御（模型无关）**

审查模型不会稳定遵守纯文本格式约定，解析端必须防御：

- 解析前先剥离 markdown 装饰字符（`*`、`_`、反引号、`#`）——模型写出 `**SCORE:** 8.5` 的频率远高于裸 `SCORE: 8.5`，不容忍装饰的匹配会把所有图静默解析成默认分。
- 分数匹配先按 `SCORE:` 主模式，失败再退宽松模式（score/rating/quality 后跟数字，容忍 `/10` 后缀）。
- 解析出的数字必须校验 0-10 范围：超范围说明匹配到的是别的数（元素计数、百分比、迭代轮次），按解析失败返回 null，禁止给默认分——虚构分与真实分进入 review log 后无法区分，居中的默认分会静默放行宽松文档类型、误杀严格类型。
- VERDICT 按行首锚定解析（多行模式匹配 `^\s*VERDICT\s*:?` 后的 ACCEPTABLE / NEEDS_IMPROVEMENT）：评分 prompt 自身会列举这两个 token 解释输出格式，纯子串匹配会把复述格式说明的审查误判为不合格图。匹配后统一大小写、空格与下划线归一再比较。
- 图像响应提取兼容两种形态：请求端仅在模型要求时附加 `modalities: ["image","text"]` 参数；响应端优先读 `message.images[]`（元素为 `type: "image_url"`、URL 是 `data:image...;base64,` 前缀的 data URI——截取逗号后内容、清除换行与空格再 base64 解码），无 images 字段时回退解析 `message.content`，以兼容不同网关与模型的返回差异。

## 5. 生成 prompt 结构要点

五要素齐备，缺一不可：

1. **类型** — 流程图 / 架构图 / 通路图 / 电路图 / 框图等
2. **组件** — 显式列出全部组件，带数量与标签；模型不会自行补全没写的组件
3. **流向** — 明确说明：从左到右 / 从上到下 / 顺时针环形
4. **标签** — 关键标注与箭头标签内容（如"每条箭头标注 activation 或 inhibition"）
5. **风格** — 视觉要求：极简框图 / 工程示意风格 / 按功能色编码（如"蓝=输入，绿=处理，红=输出"）

写法规则：

- 布局具体化："vertical flow, one box per row, generous spacing between stages"，不写"画好看点"。
- 带定量细节：n=500 screened / 1kΩ 电阻 / 784 节点输入层 / 各臂 n=175。
- 连接逐条点名："arrow from RAF to MEK labelled phosphorylation"，不写"show the cascade"。
- 颜色要求显式写出：色盲友好、灰度兼容、按功能色编码。
- 禁止把 "Figure 1:" 等图编号写进图像——编号由文档系统（LaTeX/Word）叠加。
- 禁止模糊 prompt："画个流程图""neural network""pathway diagram" 一律不合格，先补齐五要素再生成。

每个生成 prompt 默认附加的质量要求：白/浅色干净背景、高对比度、标签清晰可读（≥10pt 观感）、无衬线字体、色盲友好调色板（Okabe-Ito）、留白充足不拥挤、按需包含图例/坐标轴/比例尺。这些默认项写进 prompt 比依赖模型自觉更可靠；针对当前图再用自己的话点名强调一遍效果更好。

## 6. 定向重生成策略

重生成不是原样重跑，而是把审查 critique 点名的问题转写成改进指令并入下一轮 prompt：

1. 从 critique 提取具体问题（缺失组件、重叠位置、错误标签）
2. 在原 prompt 上追加针对性指令：更具体的布局描述、完整组件清单（含数量与标签）、逐条点名的连接
3. 重新生成并重新审查

失败模式 → 对策：

| 症状 | 对策 |
|---|---|
| 文字重叠、元素拥挤、箭头脱靶 | prompt 点名布局与间距；连接逐条命名；重跑一次——同一 prompt 两次结果不同，坏布局常是坏运气 |
| 内容缺失或科学错误 | 显式列组件 + 数量 + 标签；先读 critique，审查者通常已点名缺了什么 |
| 标签拼写错误 | 图像模型最常见失败；重跑，且使用前逐个人工读一遍所有标签 |
| 分数低于阈值但循环停止 | 已触迭代上限；保留最后一张并如实报告真实分数 |
| 分数低于图的实际水平 | 先读 critique 再决定重跑——审查者的抱怨通常具体且成立 |

## 7. 审查失败处理与日志规格

审查是第二次模型调用，可能独立失败（限流、内容过滤、返回格式无法解析）。处理规则：

- 图像已生成则一律保留；缺失的是"测量"，不是图。
- 禁止虚构分数：日志记 `"score": null`、`"reviewed": false`，原因写入 `"review_error"`，并向用户明示「审查不可用——图像已保留，质量未验证」。
- 不因审查失败自动重生成——审查者没有发言，重生成是盲猜；提示用户人工检查图像，允许重跑（此类失败通常是瞬时的）。
- 自动化判定读 `final_reviewed` 字段；`final_score` 单独无法区分"得了 7.5 分"与"从未评分"。

review log JSON 字段：

```json
{
  "user_prompt": "CONSORT participant flow diagram...",
  "doc_type": "poster",
  "quality_threshold": 7.0,
  "iterations": [
    {
      "iteration": 1,
      "image_path": "figures/consort_v1.png",
      "score": 7.5,
      "reviewed": true,
      "review_error": null,
      "needs_improvement": false,
      "critique": "SCORE: 7.5\nSTRENGTHS:..."
    }
  ],
  "final_score": 7.5,
  "final_reviewed": true,
  "early_stop": true,
  "early_stop_reason": "Quality score 7.5 meets threshold 7.0 for poster"
}
```

## 8. 出版规格清单（写 prompt 与判结果共用）

**格式与分辨率**

- 矢量优先：PDF（通用、LaTeX 友好、可嵌字体）、EPS（旧出版系统）、SVG（在线出版，并非所有期刊接受）。
- 栅格下限：出版级 300-600 DPI，线稿 600-1200 DPI，屏幕展示 150 DPI 可接受；印刷不得低于 300 DPI。
- DPI 核算：`DPI = 像素 / 最终印刷英寸`。例：2400×1800px 印 8×6 英寸 = 300 DPI，合格。
- 禁用 JPEG（有损压缩在线条图上产生伪影）、GIF（色数不足）、BMP（无压缩过大）。

**尺寸**

- 按最终印刷尺寸设计，避免事后缩放；投稿前按实际栏宽目检。
- 常用栏宽：Nature 单栏 89mm / 双栏 183mm；Science 单栏 55mm / 双栏 120mm；Cell 单栏 85mm / 双栏 178mm；PLOS 单栏 83mm / 双栏 173mm；IEEE 单栏 3.5in / 双栏 7.16in。

**期刊专属细则**

- panel 标签（A/B/C）大小写：Nature 用小写粗体（a, b, c）；Science、Cell 用大写粗体（A, B, C）。
- 文件大小上限：Nature、Science 单文件 <10MB。
- 线稿分辨率差异：Science、IEEE 线稿要求 600 DPI（照片/halftone 300 DPI 即可）；IEEE 印刷版灰度、电子版彩色。

**排版**

- 无衬线字体（Arial/Helvetica/Calibri 族）；数学密集图可用 Times New Roman。
- 最终印刷尺寸下：正文最小 6-7pt（依期刊），轴标签 8-9pt，图内标签 10-12pt，panel 标签（A/B/C）10-14pt 加粗。
- 句首大写风格（"Time (seconds)" 而非全大写）；单位放括号内（"Temperature (°C)"）；缩写在图注中全部展开；避免旋转文字（y 轴标签除外）。

**线宽**

- 图形轮廓 0.5-1.0pt，连接线/箭头 1.0-2.0pt，强调元素 2.0-3.0pt；最终尺寸下不低于 0.25pt。
- 同类元素同线宽；用线宽变化表达层级；避免印刷不可靠的发丝线。

**无障碍**

- 色盲安全调色板（Okabe-Ito）：`#E69F00` 橙、`#56B4E9` 天蓝、`#009E73` 绿、`#F0E442` 黄、`#0072B2` 蓝、`#D55E00` 朱红、`#CC79A7` 紫、`#000000` 黑。
- 备选色板（ColorBrewer）：定性用 Set2 / Paired / Dark2；顺序用 Blues / Greens / Oranges（Reds 与 Greens 避免同用）；发散用 RdBu（红-蓝）/ PuOr（紫-橙）。
- 禁止红-绿、蓝-紫、黄-浅绿相邻配对区分语义。
- 冗余编码：颜色不单独承载语义，叠加形状 / 线型（实线/虚线/点线）/ 填充图案 / 直接标注。
- 灰度可读：转灰度后仍可解释——明度分档 + 图案 + 线型差异。
- 对比度：正文 ≥4.5:1，大字号与图形元素 ≥3:1（WCAG）。
- 每图颜色 ≤3-5 种，只用于分类与强调。

**设计原则**

- 删除不贡献信息的元素；复杂图拆多 panel（A/B/C）或"总览 + 分图"。
- 最重要元素最大、最深、居中；辅助元素小而轻、靠外。
- 同形状同颜色 = 同概念，跨图一致；同关系同箭头样式。
- 网格对齐、间距均匀、标签居中；留白分组，不拥挤。
- 标签优先放形状外，远端标签用引导线；箭头含义不明时加标签或图例。

## 9. 人工终审清单

自动审查只是第一道关，交付前逐项过：

**读日志**

- [ ] review log 存在，最终轮 `"reviewed": true`
- [ ] `final_score` 是真实数字（非 null）且 ≥ 文档类型阈值
- [ ] 读过 `critique`——通过分数下审查者仍会列出遗留问题
- [ ] 多版本时对比 `_v1` / `_v2`，保留更优者

**看图（目检）**

- [ ] 每个标签拼写正确（自动审查抓不住错拼）
- [ ] 无文字重叠、无裁切
- [ ] 所有箭头连接到应连接的元素
- [ ] 科学内容正确：组件、方向、数量无误，无虚构
- [ ] 单位与计数和要求一致

**无障碍**

- [ ] 色盲安全调色板，且非颜色单独编码
- [ ] 灰度转换后仍可解读
- [ ] 相邻元素对比充足

**验证工具（投稿前跑一遍）**

- [ ] 色盲模拟：Color Oracle（免费、跨平台）或同类工具逐图检查
- [ ] PDF 技术检查：`pdfinfo` 查属性，`pdffonts` 确认字体已嵌入
- [ ] 缩放目检：400% 与 25% 两档查看，确认可缩放性
- [ ] 打印测试：按最终印刷尺寸打印，检查可读性

**出版适配**

- [ ] 与文稿其他图风格一致
- [ ] 在实际印刷栏宽下可读
- [ ] PNG 不被接受时已转换为期刊要求格式
- [ ] 图注完整、缩写全部定义
- [ ] 正文已引用该图，图在编译后的文稿中正确显示
- [ ] 交叉引用生效（`\ref{}` 指向正确的图）
- [ ] 图号与正文引用一致
- [ ] 图注相对图出现在正确页面位置
- [ ] 无与该图相关的编译警告或错误

**版本控制**

- [ ] prompt 已存档（review log 逐字记录）
- [ ] review log 与图像一同入库，分数可审计
- [ ] 复现命令已记录
