# Phase 2: PPT演示母稿 — 规范与确认门 G1

母稿是图表与页面的唯一内容源。本文件定义 PPT 演示母稿的结构、母稿规范与 G1 用户确认门。产物骨架：`templates/ppt-manuscript.md`，复制为 `doc-ppt/<project>_PPT母稿.md` 后填充。

## 母稿结构（章节顺序固定）

```
头部元信息（引用块） → 图表需求总表 → 素材图映射表 → 逐页 ## Page N 块
```

1. 头部元信息：项目名称、汇报对象、汇报范围、页面总数、演讲时长、生成日期、风格基准（showcase 门过后回填）、扩充口径（超 15 页时必填理由）——反问答案来自 Phase 1 分析报告头部
2. 图表需求总表：`| # | 页面 | 图表名 | 类型 | 核心信息 | 产物路径 | 确认状态 |`；"产物路径/确认状态"两列 Phase 2 留空，Phase 3.5 G2 通过后由 Phase 4 回写
3. 素材图映射表：`| 页面 | 素材图 | 用途 |`，无素材写"无"
4. 每个 `## Page N: <页面类型> — <简短标题>` 块含五节：`### 标题` / `### 结论` / `### 上屏内容` / `### 话术` / `### 图表需求`（类型、名称、说明、配套素材图、产物路径五字段，类型为"无"时名称写"无"）
5. `## Page N` 标记与 `### 标题` 节是脚本解析契约（`precheck_handoff.py` 页数对齐、`verify_deck_structure.py` 标题比对），格式不得改动

## PPT 母稿规范

PPT 母稿最终由 `ppt-master` 消费为**静态、可编辑、可打印分发的 PPTX**。母稿内容按以下维度执行：

| 维度 | 规范 |
|------|------|
| 最终载体 | 16:9 静态 PPTX，文字=原生文本框、图形=原生形状 |
| 呈现方式 | 静态版面，一页一次性完整呈现，无时间轴 |
| 字数密度 | 上屏文字中等密度：结论一句话 + 数据支撑 + 条目化正文，读者可自行阅读页面获取完整信息 |
| 画布尺寸 | 1920x1080 静态 HTML 中间层 → ppt-master 换算 pt（13.33x7.5in） |
| 版式体系 | 17 种布局模式选型，相邻两页不同版式；商务汇报风、品牌 Logo 页脚 |
| 图表形态 | 静态图表：XML 真源 → HTML 桥接 → 静态引用嵌入页面；禁动画/交互/hover；PPTX 中为可编辑原生形状或渲染图 |
| 素材图（源示例图） | 原图高清落盘、网格平铺上屏、不压分辨率；无 lightbox 交互 |
| 排版标注 | 母稿只标布局模式名；**禁止出现任何翻页/动画/动效/交互标注** |
| 话术去向 | `.notes` 容器 + PPTX 演讲者备注，不上屏 |

硬性规则：

1. 母稿全文（含备注）不得出现"动画、入场、转场、hover、点击放大、翻页特效"等交互动效标注；发现即按阻塞项清理
2. 每页上屏内容按"读者不看演讲也能懂"的标准写足；话术按逐字稿三铁律（150-300 字/页、口语化、关键词加粗）单独进 `### 话术` 节
3. 每页结论向核心主张收敛；面向领导层/外部客户/大众时执行 Phase 1 术语翻译规则
4. 页面总数以 Phase 1 反问答案为准；超 15 页须在头部写扩充口径与理由
5. 相邻两页布局模式不得相同（布局清单见 `slide-layout-strategies.md`），母稿阶段为每页标注布局模式名

## 起草流程

1. 从 Phase 1 分析报告 + 数据池出发，确定封面和尾页，将汇报范围内的核心信息按逻辑分组，每组对应 1-3 页
2. 为每页选页面类型与布局模式，检查节奏（连续 3 页同类型违规，封面/尾页豁免）
3. 逐页填写四要素 + 图表需求（类型/名称/说明/配套素材图），图表类型以 `robot-aiot-draw-flowchart` 支持的类型为准
4. 上屏内容必须从源文件持续提炼填满（概念与示例成对），不得只写标题级骨架
5. 章节/阶段交界处配过渡论证页（为什么从上一章进入下一章）
6. 数据全部引用数据池，估算值带 `~`；跑一遍 `governance-and-iteration.md` 交叉校验清单

## 确认门 G1（阻塞性）

1. 母稿落盘后，向用户出示完整母稿文件路径 + 逐页摘要（页码/类型/标题/结论/图表需求），并列出确认点：分页结构、汇报范围覆盖、每页结论、图表需求清单、话术口径
2. 用户确认"不需要调整" → 母稿冻结为唯一内容源，进入 Phase 3；冻结后任何内容变更走重生链并重新过 G1
3. 用户提出修改 → 修订母稿后重新送审；确认前不得调用 `robot-aiot-draw-flowchart` 绘制任何图表
4. 用户明确要求跳过 G1 直接绘图时：把用户的明确指令记入母稿头部后方可继续，不得静默跳过
5. G1 未过就绘制的图表产物一律视为无效产物，回到本门重新确认

## 阻塞条件

1. 某页四要素不完整 → 补全后再送审
2. 图表需求未明确类型和名称 → 补充后再送审
3. 上屏内容仅为标题级骨架 → 加厚后再送审
4. 出现交互动效标注（违反 PPT 母稿规范）→ 清理后再送审
5. G1 未获用户确认 → 不得进入 Phase 3
