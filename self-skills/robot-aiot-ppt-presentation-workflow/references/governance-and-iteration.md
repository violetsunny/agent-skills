# 交叉校验、重生链与迭代

本文件定义 Phase 1-5 贯穿执行的治理规则，避免数据漂移、页面漂移和手工绕过真源。

## 交叉校验清单

| 检查项 | 验证什么 | 怎么验证 |
|---|---|---|
| 数据一致性 | 同一指标在所有页面数值相同 | Grep 每个关键数字并核对出现位置 |
| 表格格式 | 表头列数与分隔行列数一致；表格块前后各有空行（GFM 渲染要求，列表项内嵌表格尤其易漏） | 逐表统计竖线字符数；扫描每个表格块首行前/末行后是否为空行 |
| 不可见字符 | 无零宽空格等 | 扫描 `\u200b`、`\u00a0` 等 |
| 估算标记 | 估算值有 `~`，精确值无 `~` | 检查同一指标的所有引用 |
| 快照与累计 | 使用提醒表覆盖全部指标 | 核查数据池提醒项 |
| 分组合计 | 分组值之和等于总计值 | 逐项相加验证 |
| 描述-数值匹配 | 文字说明与数值一致 | 通读描述并比对值 |
| 页面引用 | “用于页面”与实际引用一致 | 逐指标核对页面 |

## 常见错误

1. 分组合计不匹配
2. `~` 前缀漂移
3. 描述与数值矛盾
4. 零宽空格导致搜索或对齐失效
5. 表头加列后忘记更新 Markdown 分隔行

## 真源与重生链

```text
数据池 MD 改动
→ 母稿 MD 更新 → 重过确认门 G1（用户确认母稿）
→ 图表 XML 重生
→ 图表 HTML 重生 → 重过确认门 G2（用户确认图表）
→ 图表回写母稿（产物路径与确认状态）
→ 页面 HTML 重生
```

规则：

1. 上游变更后，本级和下游都必须按链路重生
2. 不允许跳过中间环节直接手补下游产物
3. 每次重生后必须重跑交叉校验
4. 确认门涉及的产物（母稿、图表 HTML）变更后，必须重新过对应确认门，不得沿用旧确认

明确禁止：

1. XML 改了只手改图表 HTML
2. 母稿没改却只改页面 HTML
3. 图表真源没改却只改图表 HTML
4. G1/G2 未过就推进下游（绘图/回写/页面 HTML/PPT 生成）

## Sub Agent 控制面

1. Phase 1-5 中，非 trivial 工作默认先交给 fresh sub agent，保持每阶段上下文独立干净
2. 主线程负责控制面：
   - 维护当前阶段状态
   - 决定是否允许进入下一阶段
   - 写入最终产物到 `doc-ppt/`
   - 触发跨阶段一致性校验与重生链
3. sub agent 负责工作面：
   - 数据提取与口径归并建议
   - 受众分层与术语翻译草稿
   - 图表结构规划与页面内容草稿
   - 页面审查、数据核对、交付前检查
4. sub agent 产出必须回到主线程汇总后，才允许写文件或触发下一阶段
5. tiny 单点修正可跳过 sub agent，直接由主线程处理

## 迭代循环

```text
起草页面 → 用户审查 → 识别问题 → 修正 → 交叉校验 → 用户审查 → 重复
```

## 迭代原则

1. 多做减法，少做加法
2. 每次改动后全文校验，并确认重生链同步
3. 每轮迭代后从目标受众视角通读，确认 30 秒内能理解核心结论
4. 内容过载页优先页内样式重组（标题精简、长文改数字卡、头部压缩），不拆页；重组允许删改冻结逐字稿的屏上文字，但必须同步三处：①notes/*.md 与 pages/*.html `.notes` 话术双源一致（`check_notes.py --sync` 验证）②母稿上屏文字栏 ③校验改走 `compare_text.py --mode coverage`（SVG 重绘路线）或重生成 expected_text.txt（桥接逐字路线）

## 页面合并检查

1. 两页讲同一闭环且数据锚点重叠超过 50% 时，优先考虑合并
2. 合并后仍需满足“一页一主题”
3. 合并后重新跑布局审查，防止内容溢出

## 协作链路

```text
本技能
├── 主线程: 负责阶段编排、落盘、阻塞校验、确认门（G1/G2）、最终交付
├── Sub agents: 负责阶段内分析/起草/审查
├── Phase 2: 主线程产出 PPT 演示母稿，G1 用户确认后冻结
├── Phase 3: 主线程调用 robot-aiot-draw-flowchart 生成图表 XML
├── Phase 3.5: 主线程调用 robot-aiot-draw-flowchart 的 XML→HTML 桥接能力，G2 用户确认图表
├── Phase 4: 主线程回写图表到母稿，再调用 robot-aiot-draw-flowchart 的静态页面 HTML 能力生成逐页 HTML
└── Phase 5: 主线程调用 ppt-master
```

## 实战经验沉淀

1. 多数据源合并必须先统一口径，否则分组合计一定出错
2. 技术术语不按受众翻译，汇报版会立即失去可读性（技术同行受众除外）
3. 布局审查不是可选项，问题常常在 PPT 阶段才暴露
4. 视觉增强必须与布局分层，否则很容易破坏已验证布局
5. 主动合并内容重叠页面，通常比继续加页更有效
6. PPTX 质量常按“结构 → 数据 → 视觉”三轮收敛
