# Phase 4: 图表回写母稿与逐页 HTML

母稿已在 Phase 2 产出并经 G1 确认，图表已在 Phase 3/3.5 产出并经 G2 确认。Phase 4 负责：先把确认后的图表回写母稿对应页，再把母稿逐页落成单页 HTML；逐页 HTML 的规则所有权已内化到 `robot-aiot-draw-flowchart` 的静态页面 HTML 能力中。

## 图表回写（先于一切页面工作，阻塞性）

1. 回写内容：每张图表的产物路径（`flow/<chart-name>.xml` / `flow/<chart-name>.html`）与确认状态（G2 通过日期）写入母稿"图表需求总表"对应行；对应 `## Page N` 块的 `### 图表需求` 节补"产物路径"字段
2. 回写完整性校验：图表需求总表中类型非"无"的行必须有产物路径与确认状态；任何页缺图表路径、或路径指向不存在/未确认的产物，不得开始逐页 HTML
3. 回写只做登记，不得借机改动母稿的标题/结论/上屏内容/话术；发现内容问题回 Phase 2 修订母稿并重过 G1
4. 回写完成后母稿即"整体准备好"的完整内容源，逐页 HTML 与 ppt-master 只消费该母稿

## 本文件只保留逐页 HTML 入口约束

1. 母稿回写完成前不得开始写任何页面 HTML
2. 调用 `robot-aiot-draw-flowchart` 的静态页面 HTML 能力把每页落成 HTML，调用时必须传递 Phase 1 确认的目标受众（受众→刻度/风格基调映射由 `slide-premium-design.md` 决定，未指定默认领导层）
3. 每页必须满足"标题 / 结论 / 上屏内容 / 话术"四要素
4. 话术按逐字稿三铁律写作（每页 150-300 字、口语化、关键词加粗提示信号，规则见 `slide-layout-strategies.md`），并随页面 HTML 写入 `display:none` 的 `.notes` 容器，禁止出现在页面可见区域
5. 页面 HTML 落 `doc-ppt/pages/`，图表只引用已回写母稿且 G2 确认的 `doc-ppt/flow/<图表名>.html`，页面内引用图表用 `../flow/<图表名>.html` 相对路径
6. 页面画布外包 scale-to-fit 视口自适应壳：浏览器任意窗口尺寸下画布等比缩放居中、无滚动条完整可见，`1920x1080` 视口时 scale=1（实现见 `slide-page-authoring.md`）
7. 素材图盘点：母稿素材图映射表中有的必须上屏；母稿未指定但资源目录存在素材图时，向用户确认是否选配，不得静默忽略。静态交付形态不加 lightbox JS 交互
8. 母稿排页后逐对检查相邻两页布局模式不得相同（见 `slide-layout-strategies.md` Deck 级硬规则）
9. 页面完成后，必须按 `robot-aiot-draw-flowchart` 的布局清单审查通过后才能进入 Phase 5
10. 逐页 HTML 全面铺开前必须过两页 showcase 门：先产出 2 页代表性页面经用户确认风格/版式/配色，再批量生成其余页（规则见下方"两页 showcase 门"，阻塞性）

## 两页 showcase 门（阻塞性）

showcase 门是"先预览再定稿"的选型流程：用 2 页真实页面（封面 + 一个核心内容页）同时验证风格、版式、图表语法与配色落地，经用户确认后再批量铺开其余页。目的是把方向性返工的成本封顶在 2 页，不让它放大成整套 N 页。

### 触发条件

满足任一即触发：

1. deck 总页数 ≥ 5
2. 用户未指定风格，且本项目没有已确认的风格基准（首次制作，或既有基准未锁定）
3. 用户中途要求更换风格（视为重新过门）

豁免须同时满足：总页数 < 5，且风格基调与风格选型已由用户确认（如沿用本项目上一套已锁定的风格基准）。豁免时在母稿头部显式声明"已豁免 showcase 门"及理由，不得静默跳过。

### showcase 页选择标准

1. 固定一页为封面页（Title 布局）：验证主色与首页架构图的一致性、字体配对、Logo 页脚、标题层级
2. 另一页取与封面视觉结构差异最大、信息密度最高的核心内容页，按汇报场景推荐：

| 汇报场景 | 推荐内容页 | 验证重点 |
|---|---|---|
| 业务汇报 / QBR | 数据看板页（Metrics Dashboard） | KPI 卡语法、表格体数字、图表引用槽位 |
| 方案 / 立项汇报 | 方案架构页（Solution 或 Split，引用 `flow/` 图表 HTML） | 图表 HTML 外框衔接、结论层版式 |
| 产品 / 成果发布 | 功能展示页（Feature Grid 或 Screenshot） | 卡片节奏、素材图上屏语法 |
| 复盘 / 总结 | 成果对照页（Diff 或 Big Number） | 对照高亮、大数字记忆点 |

3. 两页必须使用母稿真实标题、真实数据、真实图表，禁止占位文案与示意数据；必须满足全部 Phase 4 硬约束（四要素、`.notes` 逐字稿、scale-to-fit 壳、Logo 页脚）——showcase 门不豁免任何规则
4. 风格从 `slide-layout-strategies.md` 的"PPT 风格精选"选定，内容页布局从 17 种布局模式选定；这两页过门即锁定整套视觉语法基准

### 确认门流程

1. 母稿排页完成后，按上述标准选出 2 页，调用 `robot-aiot-draw-flowchart` 的静态页面 HTML 能力先落这 2 页，落盘 `doc-ppt/pages/`
2. 向用户提供预览（浏览器直接打开两页 HTML），并列出四项确认点：风格基调与风格选型 / 版式结构 / 配色体系（含与首页架构图主色一致性）/ 字级层级与信息密度
3. 用户确认通过 → 把风格基准写入母稿头部（风格名、基调、主色、字体配对、密度档位），整套锁定，再批量铺开其余 N-2 页，每页从锁定基准派生，不得引入基准外的新强调色、新字体、新版式家族
4. 用户提出修改 → 只改这 2 页并重新提交确认，确认通过前不得开始其余页面
5. 过门后风格不得再变；用户要求全局换风格时按重生链处理（`governance-and-iteration.md`）：先改 2 页 showcase 重新过门，再刷新全套

### 未过门的处置

1. 未过门（用户未确认或要求修改中）不得生成其余任何页面；违反铺开按阻塞项处理，与"没有 HTML 不得生成 PPT"同级
2. 已经未过门就铺开的：立即停止批量生成，回退到 showcase 步骤补过门；已生成页面按确认后的基准逐页复核，不符合的页面重做
3. 用户明确要求跳过确认直接出全套时：把用户的明确指令记入母稿头部后方可铺开；仍建议先出 2 页随全套一并交付，把确认合并为一次
