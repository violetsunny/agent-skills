# 分页策略与母稿模板

本文件定义 Phase 2 母稿分页的执行规则和模板。

## 分页原则

### 页面粒度

1. 一页一个主题，30 秒内可读懂核心结论
2. 页面总数默认控制在 5-15 页
3. 超出 15 页时合并相近主题或拆分为多套演示；**用户明确要求扩充时可突破上限**，条件是：做节奏校验、在母稿头部记录扩充口径与理由
4. 少于 5 页时检查是否有遗漏的关键信息
5. 主体章节（承载汇报主线的部分）页数占比须与其分量匹配，篇幅不足时优先扩充主体章节而非平均加页；判定锚点：源文档篇幅最大的主线章节，其页数应为全场最多且不低于总页数 1/3

### 页面类型

| 类型 | 用途 | 典型位置 |
|------|------|----------|
| 封面 | 项目名称、汇报人、日期 | 第 1 页 |
| 概览 | 全局结论、核心指标一览 | 第 2 页 |
| 架构图 | 系统组成、技术栈、部署拓扑 | 前段 |
| 流程图 | 业务流程、数据流、控制流 | 中段 |
| 数据看板 | KPI、趋势、对比 | 中段 |
| 案例 | 典型场景、实施效果 | 后段 |
| 过渡论证 | 章节/阶段切换的必然性论证（见下节） | 章节交界处 |
| 总结 | 下一步计划、待决事项 | 倒数第 2 页 |
| 尾页 | 致谢、联系方式 | 最后 |

### 节奏控制

1. 连续 3 页同类型必须插入过渡页或换版式
2. 数据密集页后接结论页或案例页，避免疲劳
3. 封面和尾页不计入节奏统计

### 过渡论证页（章节/阶段交界必配）

多章节/多阶段叙事的演示，章节切换处必须独立成页回答"为什么从上一章进入下一章"，不得靠一句话带过。论证链模板：

1. 上一章能力边界：它解决了什么、解决不了什么（天花板）
2. 替代方案逐项检验：候选方案逐一验证能否补上缺口（是/否/部分）
3. 共同根因：所有"否/部分"收敛到的单一结构性根因
4. 必然方向：根因决定下一章的核心机制是必然选择而非偏好

### 内容厚度规则

1. 每页"上屏内容"必须从源文档持续提炼填满，不得只写标题级骨架；母稿是 Phase 4 的唯一内容源，母稿薄则页面必薄
2. **概念与示例成对**：每个概念性论点配一个具体示例（真实界面截图、报文样例、场景走查等），示例素材优先取自 Phase 1 素材图清单
3. **图表与素材图并举**：新绘图表表达结构与逻辑，素材截图提供真实佐证，两者在同一页配合出现
4. 每页图表需求须标注"配套素材图"（引用素材图清单中的路径），无素材可配时显式写"无"

## 母稿模板

每页按以下结构定义：

```markdown
## Page N: <页面类型> — <简短标题>

### 标题
<页面主标题，≤ 2 行>

### 结论
<领导应该带走的核心判断，一句话>

### 上屏内容
- <图表/数字/列表/流程的具体内容>
- <数据来源标注>

### 话术
<口头解释要点，不复述屏幕文字，补充背景和动作>

### 图表需求
- 类型：<架构图/流程图/数据图/拓扑图/映射图/泳道图/循环图/生命周期图/脑图/分流汇聚图/对比图/层级图/时序图/无 等>
- 名称：<chart-name>（用于文件名和引用）
- 说明：<图表要表达的核心信息>
- 配套素材图：<素材图路径列表 / 无>
```

图表类型开放枚举，以 `robot-aiot-arch-diagram` 支持的视觉类型为准（Phase 3 路由表负责映射）；母稿标记新类型时同步在 Phase 3 路由表补一行映射。

## 分页决策流程

1. 从 Phase 1 内容分析报告出发
2. 确定封面和尾页（固定）
3. 将核心信息按逻辑分组，每组对应 1-3 页
4. 为每组选择合适的页面类型
5. 检查节奏：连续同类型是否超限
6. 为每页填写四要素模板
7. 标记图表需求

## 阻塞条件

1. 某页四要素不完整 → 补全后再继续
2. 图表需求未明确类型和名称 → 补充后再继续
3. 页面总数超出默认上限且无用户明确扩充要求 → 重新合并或拆分
4. 章节交界处缺过渡论证页 → 补页后再继续
5. 上屏内容仅为标题级骨架、未从源文档提炼 → 加厚后再继续
