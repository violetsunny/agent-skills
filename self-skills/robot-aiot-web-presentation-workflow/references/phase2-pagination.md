# 分页策略与母稿模板

本文件定义 Phase 2 Web 演示母稿的执行规则、Web 母稿规范与确认门 G1；产物骨架在 `templates/deck-manuscript.md`。

## Web 母稿规范

Web 母稿最终产出**浏览器运行的动画特效 HTML**（`robot-aiot-interactive-html-author` 编写）。母稿内容按以下维度执行：

| 维度 | 规范 |
|------|------|
| 最终载体 | 单文件 deck（默认）/多页/竖版/滚动叙事 HTML，双击浏览器运行，零依赖 |
| 呈现方式 | 动效分步呈现：入场/转场/数据动效按时间轴展开 |
| 字数密度 | 上屏文字克制：文字是视觉锚点，完整信息由动画分步与话术承载 |
| 画布尺寸 | 1920x1080 设计画布 + scale-to-fit 壳（竖版 1080x1920） |
| 版式体系 | 登记版式 S/M 系 + 主题节奏表（单色系 light/dark + hero）+ 能量段位表（四段位运镜输入） |
| 图表形态 | SVG 内嵌，允许入场动画、数据计数、交互高亮 |
| 素材图（源示例图） | 压缩缩略图 + 网格平铺 + 点击放大 lightbox |
| 排版标注 | 每页必带"动效与交互备注"节（入场/转场/数据动效/交互点/DOM 预算） |
| 话术去向 | 页面 `.notes` 容器（display:none），不上屏 |

硬性规则：

1. 每页 Page 块在四要素之外必带 `### 动效与交互备注` 节：入场动画、转场方式、数据动效（计数/生长）、交互点（hover/点击/lightbox）、DOM 预算提示（≤500）；无动效的静态页也要保留该节并写"静态页，仅转场"
2. 上屏内容按"锚点文字 + 动画分步展开"规划：一个论点一个动画步，不得把整段文字一次性堆上屏
3. 图表槽位按可动画 SVG 内嵌规划；素材图按压缩缩略图 + lightbox 规划

## 分页原则

### 页面粒度

1. 一页一个主题，30 秒内可读懂核心结论
2. 页面总数默认控制在 5-15 页
3. 超出 15 页时合并相近主题或拆分为多套演示；**用户明确要求扩充时可突破上限**，条件是：做节奏校验、在母稿头部记录扩充口径与理由
4. 少于 5 页时检查是否有遗漏的关键信息
5. 主体章节（承载汇报主线的部分）页数占比须与其分量匹配，篇幅不足时优先扩充主体章节而非平均加页；判定锚点：源文档篇幅最大的主线章节，其页数应为全场最多且不低于总页数 1/3

### 页面类型

| 类型 | 用途 | 典型位置 |
|------|------|----------|
| 封面 | 项目名称、汇报人、日期 | 第 1 页 |
| 概览 | 全局结论、核心指标一览 | 第 2 页 |
| 架构图 | 系统组成、技术栈、部署拓扑 | 前段 |
| 流程图 | 业务流程、数据流、控制流 | 中段 |
| 数据看板 | KPI、趋势、对比 | 中段 |
| 案例 | 典型场景、实施效果 | 后段 |
| 过渡论证 | 章节/阶段切换的必然性论证（见下节） | 章节交界处 |
| 总结 | 下一步计划、待决事项 | 倒数第 2 页 |
| 尾页 | 致谢、联系方式 | 最后 |

### 节奏控制

1. 连续 3 页同类型必须插入过渡页或换版式
2. 数据密集页后接结论页或案例页，避免疲劳
3. 封面和尾页不计入节奏统计

### 过渡论证页（章节/阶段交界必配）

多章节/多阶段叙事的演示，章节切换处必须独立成页回答"为什么从上一章进入下一章"，不得靠一句话带过。论证链模板：

1. 上一章能力边界：它解决了什么、解决不了什么（天花板）
2. 替代方案逐项检验：候选方案逐一验证能否补上缺口（是/否/部分）
3. 共同根因：所有"否/部分"收敛到的单一结构性根因
4. 必然方向：根因决定下一章的核心机制是必然选择而非偏好

### 内容厚度规则

1. 每页"上屏内容"必须从源文档持续提炼填满，不得只写标题级骨架；母稿是 Phase 4 的唯一内容源，母稿薄则页面必薄
2. **概念与示例成对**：每个概念性论点配一个具体示例（真实界面截图、报文样例、场景走查等），示例素材优先取自 Phase 1 素材图清单
3. **图表与素材图并举**：新绘图表表达结构与逻辑，素材截图提供真实佐证，两者在同一页配合出现
4. 每页图表需求须标注"配套素材图"（引用素材图清单中的路径），无素材可配时显式写"无"

## 母稿模板

成品骨架：`templates/deck-manuscript.md`（复制为 `doc-web/<project>_演示母稿.md` 后填充，章节顺序与表头不得改动，`scripts/lint_manuscript.py` 按此解析）。

每个 Page 块含六节：标题 / 结论 / 上屏内容 / 话术 / 动效与交互备注 / 图表需求（类型、名称、说明、配套素材图、产物路径五字段；产物路径 Phase 2 留空，Phase 3.5 图表回写时填充）。

图表类型开放枚举，以 `robot-aiot-arch-diagram` 支持的视觉类型为准（Phase 3 路由表负责映射）；母稿标记新类型时同步在 Phase 3 路由表补一行映射。

## 分页决策流程

1. 从 Phase 1 内容分析报告出发
2. 确定封面和尾页（固定）
3. 将核心信息按逻辑分组，每组对应 1-3 页
4. 为每组选择合适的页面类型
5. 检查节奏：连续同类型是否超限
6. 为每页填写四要素模板
7. 标记图表需求

## 产物

输出文件：`doc-web/<project>_演示母稿.md`，直接以 `templates/deck-manuscript.md` 为骨架填充。

填充完成后必须跑 `python3 scripts/lint_manuscript.py <母稿路径>`，`[MS-FAIL]` 清零才能送 G1 确认门；`[MS-WARN]` 逐条人工确认（脚本检查项与本文件阻塞条件、节奏控制、主题节奏、能量段位规则一一对应）。

## 确认门 G1（阻塞性）

1. 母稿 lint 清零后，向用户出示完整母稿文件路径 + 逐页摘要（页码/类型/标题/结论/图表需求/动效要点），并列出确认点：分页结构、汇报范围覆盖、每页结论、图表需求清单、动效与交互幅度、话术口径
2. 用户确认"不需要调整" → 母稿冻结为图表与页面的唯一内容源，进入 Phase 3；冻结后任何内容变更须修订母稿、重跑 lint 并重新过 G1
3. 用户提出修改 → 修订母稿后重新送审；确认前不得调用 `robot-aiot-arch-diagram` 绘制任何图表
4. 用户明确要求跳过 G1 直接绘图时：把用户的明确指令记入母稿头部后方可继续，不得静默跳过
5. G1 未过就绘制的图表产物一律视为无效产物，回到本门重新确认
6. 与两页 showcase 确认门的关系：G1 确认母稿内容（说什么、分几页、什么动效），showcase 门确认视觉风格（长什么样）；顺序为先 G1、后 showcase，两门不得互相替代

## 阻塞条件

1. 某页四要素不完整 → 补全后再继续
2. 某页缺"动效与交互备注"节（Web 母稿必备）→ 补全后再继续
3. 图表需求未明确类型和名称 → 补充后再继续
4. 页面总数超出默认上限且无用户明确扩充要求 → 重新合并或拆分
5. 章节交界处缺过渡论证页 → 补页后再继续
6. 上屏内容仅为标题级骨架、未从源文档提炼 → 加厚后再继续
7. G1 未获用户确认 → 不得进入 Phase 3

## 主题节奏规划（全 deck 单色系，母稿阶段先行）

deck 将使用登记版式（S/M 系，见 `robot-aiot-interactive-html-author/references/swiss-layout-system.md`）时，主题节奏必须在母稿阶段规划完成，不留到写页时临场决定：

1. 规划时机：分页决策流程第 5 步（节奏检查）完成后、第 6 步填写四要素模板前，先定色系（全 light 或全 dark）再画 hero 分布表；跳过规划直接写页 = 成品无 hero 呼吸点
2. 母稿产物在"素材图映射表"之后新增主题节奏表（表头与示例见 `templates/deck-manuscript.md`）；不使用登记版式时在表内写"本 deck 不使用登记版式"备注行，不得整节省略
3. 全 deck 单色系：主题档只取同一色系的普通档 + hero 档（全 light 系 = light/hero light；全 dark 系 = dark/hero dark），禁止 light/dark 两系混排交替；色系由受众+场景+情绪基调推断，用户明示偏好优先
4. 主题档四选一：light / dark / hero light / hero dark；hero 页放章节交界（封面、幕封、问题页、大引用），非 hero 页承载正文，不连续超过 2 页 hero
5. 完整节奏硬规则、逐版式主题默认值表、8 页节奏模板 → `robot-aiot-interactive-html-author/references/web-slide-strategies.md`"登记版式主题节奏（全 deck 单色系）"节，本文件不重复；版式骨架与选择索引 → `swiss-layout-system.md`
6. 阻塞条件补充：登记版式 deck 缺主题节奏表、或混入异色系 → 调整后再继续

## 能量骨架段位规划（母稿阶段先行）

母稿分页时按四段位规划全 deck 能量曲线——能量不平均分配，先划段位再排页。规划时机与主题节奏表相同：分页决策流程第 5 步（节奏检查）完成后、第 6 步填写四要素模板前。能量段位与主题节奏是两条独立线，各自规划、各自校验；与"节奏控制"节的衔接：节奏控制管相邻页的局部类型交替，能量段位管全场曲线。

四段位与母稿层规划要点：

| 段位 | 页数占比 | 能量特征 | 母稿层动作 |
|------|----------|----------|------------|
| ① 开场峰 | 前 1-2 页（8-12%） | 高印象、低运动；"峰"是视觉印象不是信息量 | 封面与概览承载核心主张的第一次亮相，不排高密度信息 |
| ② 铺垫谷 | 12-15% | 全场能量最低、信息密度最高 | 排架构图/表格/背景摸底页，给观众进入叙事的时间 |
| ③ 中段起伏 | 55-65% | 中高与低交替，每个高点绑一个叙心理由 | 数据看板/流程图/案例页交替排布；过渡论证页与章节页是天然呼吸点，排低点位置 |
| ④ 收尾峰 | 末 13-16% | 全场能量峰值 | 倒数第二页放最强结论与关键数字；总结页收敛、末页谢幕 |

执行规则：

1. 分页决策流程第 5 步完成后，先按上表划出段位区间（哪几页属哪段），再落每页的内容厚度与页面类型
2. 母稿产物在主题节奏表之后（无主题节奏表时在素材图映射表之后）新增能量段位表（表头与示例见 `templates/deck-manuscript.md`）；段位四选一：开场峰 / 铺垫谷 / 中段起伏 / 收尾峰，能量级三选一：高 / 中 / 低

3. 母稿阶段自检：四段位齐全——8 页以下 deck 允许铺垫谷并入中段前部，但开场峰与收尾峰不可省；无全平能量（无峰 = 无记忆点）；铺垫谷不落尾部；收尾峰的峰值页（倒数第二页）不被总结页杂项挤占
4. 本表是 Phase 4 运镜规划的能量输入：段位级运镜策略、排片纪律（先划静止预算再排运镜）、逐页运镜参数与校验细则 → `robot-aiot-interactive-html-author/references/camera-storyboard.md` §12"能量骨架"，本文件只做母稿层的段位划分与能量级标注，不复制运镜细节
5. 阻塞条件补充：母稿缺能量段位表、或全场能量无峰 → 调整后再继续

## 两页 showcase 确认门（母稿完成后、全面铺开前）

母稿通过 G1 确认门后、Phase 3/4 全面铺开前，先制作 2 页代表性页面作 showcase 交用户确认，用两页锁定全套 deck 的风格基调、信息密度与交互幅度，避免方向错误到全量完成才暴露。本门是 SKILL.md G1→Phase 3 切换的细化：全面铺开前先对 2 页跑一遍 Phase 3→Phase 4 的小闭环（其图表随 showcase 一并送用户确认，视同该批图表的 G2），确认通过后其余页面回到正常编排，SKILL.md 各阶段阻塞条件（含其余图表的 G2）对其余页面照常生效。

1. 触发时机：G1 确认通过后、Phase 3 批量图表生成前；deck ≤ 6 页且用户已在标题页预览中确认过风格时，经用户明确同意可跳过，不得静默跳过
2. 选页标准（两类各取一页，覆盖全场差异最大的两种页面形态）：
   - 高能量页 1 张：开场峰或收尾峰页（封面/概览/最强结论页），验证视觉冲击与 hero 版式
   - 高密度页 1 张：铺垫谷或中段数据/架构页，验证信息密度、图表+素材图并举与可读性
   - 高密度页优先承载母稿中最复杂的图表类型，让 Phase 3 路由与全局风格 token 提前受检
3. 制作方式：这 2 页先行走 Phase 3（其所需图表）与 Phase 4（页面 HTML），产物按 SKILL.md 输出目录约定落对应目录；制作输入含母稿四要素、主题节奏表、能量段位表
4. 确认门：向用户出示 2 页，确认点三项——风格基调是否匹配情绪基调（Phase 1 form 五问第 4 问）、信息密度是否合适、交互与动画幅度是否可接受；用户确认后全场基准锁定，其余页面按此基准制作，不再逐页征求风格意见
5. 未过处置：用户提出修改 → 修改 showcase 页后再次送审，通过前不得全面铺开；修改波及母稿（分页/四要素/图表需求）→ 回 Phase 2 修订母稿并重走本门；连续两轮未过 → 暂停，与用户重新对齐风格选型输入（回到三标题页预览定稿流程）后再继续
6. 与标题页预览定稿的关系：用户无风格偏好且三标题页预览尚未定稿时，两个确认门合并到同一轮交互（先定标题页风格，再按该风格出两页 showcase），避免分散打扰；showcase 通过后，SKILL.md Phase 4 验收自检中"三标题页预览已出并经用户定稿"一项视为已由 showcase 流程覆盖
