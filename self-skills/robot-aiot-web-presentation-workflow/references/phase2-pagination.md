# 分页策略与母稿模板

本文件定义 Phase 2 母稿分页的执行规则和模板。

## 分页原则

### 页面粒度

1. 一页一个主题，30 秒内可读懂核心结论
2. 页面总数控制在 5-15 页
3. 超出 15 页时合并相近主题或拆分为多套演示
4. 少于 5 页时检查是否有遗漏的关键信息

### 页面类型

| 类型 | 用途 | 典型位置 |
|------|------|----------|
| 封面 | 项目名称、汇报人、日期 | 第 1 页 |
| 概览 | 全局结论、核心指标一览 | 第 2 页 |
| 架构图 | 系统组成、技术栈、部署拓扑 | 前段 |
| 流程图 | 业务流程、数据流、控制流 | 中段 |
| 数据看板 | KPI、趋势、对比 | 中段 |
| 案例 | 典型场景、实施效果 | 后段 |
| 总结 | 下一步计划、待决事项 | 倒数第 2 页 |
| 尾页 | 致谢、联系方式 | 最后 |

### 节奏控制

1. 连续 3 页同类型必须插入过渡页或换版式
2. 数据密集页后接结论页或案例页，避免疲劳
3. 封面和尾页不计入节奏统计

## 母稿模板

每页按以下结构定义：

```markdown
## Page N: <页面类型> — <简短标题>

### 标题
<页面主标题，≤ 2 行>

### 结论
<领导应该带走的核心判断，一句话>

### 上屏内容
- <图表/数字/列表/流程的具体内容>
- <数据来源标注>

### 话术
<口头解释要点，不复述屏幕文字，补充背景和动作>

### 图表需求
- 类型：<架构图/流程图/数据图/无>
- 名称：<chart-name>（用于文件名和引用）
- 说明：<图表要表达的核心信息>
```

## 分页决策流程

1. 从 Phase 1 内容分析报告出发
2. 确定封面和尾页（固定）
3. 将核心信息按逻辑分组，每组对应 1-3 页
4. 为每组选择合适的页面类型
5. 检查节奏：连续同类型是否超限
6. 为每页填写四要素模板
7. 标记图表需求

## 产物

输出文件：`doc-web/<project>_演示母稿.md`

文件结构：
```markdown
# <项目名称> 交互演示母稿

> 汇报对象：<...>
> 汇报场景：<...>
> 生成日期：<YYYY-MM-DD>

---

## Page 1: 封面 — <标题>
...

## Page 2: 概览 — <标题>
...
```

## 阻塞条件

1. 某页四要素不完整 → 补全后再继续
2. 图表需求未明确类型和名称 → 补充后再继续
3. 页面总数超出 15 页 → 重新合并或拆分
