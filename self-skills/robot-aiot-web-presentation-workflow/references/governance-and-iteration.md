# 交叉校验、重生链与迭代

本文件定义 Phase 1-4（含 Phase 3.5 回写）贯穿执行的治理规则，避免内容漂移、图表漂移、页面漂移和手工绕过真源。

## 交叉校验清单

| 检查项 | 验证什么 | 怎么验证 |
|---|---|---|
| 数据一致性 | 同一指标在所有页面/图表数值相同 | grep 每个关键数字并核对出现位置 |
| 估算标记 | 估算值有 `~`，精确值无 `~`；厂商参考值/示例值已标注 | 检查同一指标的所有引用 |
| 不可见字符 | 无零宽空格等 | 扫描 `\u200b`、`\u00a0` |
| 母稿四要素 | 每页标题/结论/上屏内容/话术齐备 + 动效与交互备注节 | `lint_manuscript.py` + 逐页核对 |
| 图表需求总表回写 | 类型非「无」行的产物路径指向存在的 flow 文件、确认状态列已填 | `check_phase_handoff.py --phase 3.5` |
| 话术隐藏 | `.notes` 容器 `display:none` 零泄漏 | `check_notes_hidden.py` |
| 页面静态硬约束 | stage 1920x1080 / footer.bar / h1 / fit / reduced-motion / DOM≤500 / 禁色零命中 | `check_deck_batch.py` |
| SVG 线/箭头契约 | 箭头分离 polygon、虚线 mask reveal、anim-flow 豁免 | `lint_deck_html.py` #8 |
| 组件 CSS 定义 | 页内使用任一右栏组件前该页 CSS 含其定义 | `lint_deck_html.py` #9 |
| 平铺散文 | 右栏无连续 ≥2 句散文裸文本、无长 li ul | `lint_deck_html.py` #10 |
| 交互反馈 | `:focus-visible` 与 hover 反馈在位 | `lint_deck_html.py` #11 |
| 动画触发 | t100/t6000 双时间点截图逐页字节有差异（静态页豁免） | `shoot_anim.py` |
| 滚动叙事页验收 | 1440px 基准 + @media 断点 + 100vh 首屏 / 单 `<section>` DOM≤500 / 平铺散文禁与 deck 同阈值（全局美学）/ #8/#9/#11 同 deck | `lint_landing_html.py` |

## 常见错误

1. 母稿薄：上屏内容只写标题级骨架，未从源文档提炼填满
2. 图表需求总表回写漏：产物路径空、确认状态空、或路径指向不存在的 flow 文件
3. G1/G2 未过就推进下游（绘图/回写/页面 HTML）
4. 右栏组件使用无页内 CSS 定义，静默退化为裸文本
5. 右栏文字平铺：连续 ≥2 句散文未改组件
6. 零宽空格导致搜索或对齐失效
7. 全 deck 混入异色系（light/dark 逐页交替）
8. 静态页未以 `--static-pages` 传入，动画触发检查误报

## 真源与重生链

```text
内容分析报告 改动
→ 母稿 MD 更新 → 重过确认门 G1（用户确认母稿）
→ flow/ 图表 SVG+HTML 重生 → 重过确认门 G2（用户确认图表）
→ 图表回写母稿（产物路径与确认状态）
→ 页面 HTML 重生
```

规则：

1. 上游变更后，本级和下游都必须按链路重生
2. 不允许跳过中间环节直接手补下游产物
3. 每次重生后必须重跑交叉校验
4. 确认门涉及的产物（母稿、图表 HTML）变更后，必须重新过对应确认门，不得沿用旧确认
5. 图表真源是 SVG，HTML 由 SVG 内联生成；改图表必须改 SVG 再重生 HTML，禁止只改 HTML

明确禁止：

1. SVG 改了只手改图表 HTML
2. 母稿没改却只改页面 HTML
3. 图表真源没改却只改图表 HTML
4. G1/G2 未过就推进下游（绘图/回写/页面 HTML）

## 交接（handoff）治理

每个环节结束后，除确认门外还须做交接校验，确保「本环节产物存在 + 确认门状态已记录 + 下一环节输入齐备」三件事同时成立，FAIL 阻塞不得推进：

1. 校验命令：`scripts/check_phase_handoff.py <输出目录> --phase N --write`（N ∈ 1/2/3/3.5/4），落盘 `_gen/handoff-phaseN.md` 交接记录
2. 确认门状态更新动作（主线程负责，机检只读不写）：
   - G1 通过后把母稿头部「确认状态」字段更新为「G1 已通过（日期）」
   - G2 通过后把母稿头部「确认状态」字段更新为「G2 已通过（日期）」
   - 字段含尖括号占位符视为未填充，机检判门未通过
3. 机检口径：只校验确认状态字段已标记「已通过」，不替代用户语义确认（与确认门「用户确认不需要调整/图表无误」是两件事）
4. handoff 不替代质量验收：Phase 4 的 handoff 只校验最终 HTML 存在，页面质量另跑「交叉校验清单」全链（lint_deck_html / check_deck_batch / check_notes_hidden / shoot_anim；滚动叙事页跑 lint_landing_html）
5. 重生链触发后，受影响环节及其下游的 handoff 须重跑（如母稿改动重过 G1 后，Phase 2/3/3.5/4 的 handoff 依次重校验）
6. 交接记录 `_gen/handoff-phaseN.md` 的「遗留风险 / 待办」节由主线程补充，无则写「无」

## Sub Agent 控制面

1. Phase 1-4 中，非 trivial 工作默认先交给 fresh sub agent，保持每阶段上下文独立干净
2. 主线程负责控制面：
   - 维护当前阶段状态与确认门状态字段
   - 决定是否允许进入下一阶段（含 handoff 校验）
   - 写入最终产物到输出目录
   - 触发跨阶段一致性校验与重生链
3. sub agent 负责工作面：
   - 内容提取与汇报定位推断草稿
   - 受众分层与术语翻译草稿
   - 图表结构规划与页面内容草稿
   - 页面审查、数据核对、交付前检查
4. sub agent 产出必须回到主线程汇总后，才允许写文件或触发下一阶段
5. tiny 单点修正可跳过 sub agent，直接由主线程处理

## 迭代循环

```text
起草页面 → 用户审查 → 识别问题 → 修正 → 交叉校验 → 用户审查 → 重复
```

## 迭代原则

1. 多做减法，少做加法
2. 每次改动后全文校验，并确认重生链同步
3. 每轮迭代后从目标受众视角通读，确认 30 秒内能理解核心结论
4. 内容过载页优先页内样式重组（标题精简、长文改数字卡/组件、头部压缩），不拆页；重组允许删改冻结母稿的屏上文字，但必须同步：①母稿上屏内容栏 ②页面 HTML ③`.notes` 话术（`check_notes_hidden.py` 验证隐藏）
5. 全 deck 单色系不混排：迭代改页时保持主题节奏表与能量段位表一致，hero 页不连续超过 2 页

## 页面合并检查

1. 两页讲同一闭环且数据锚点重叠超过 50% 时，优先考虑合并
2. 合并后仍需满足「一页一主题」
3. 合并后重新跑布局审查与 `check_deck_batch.py`，防止内容溢出或 DOM 超预算

## 协作链路

```text
本技能
├── 主线程: 负责阶段编排、落盘、阻塞校验、确认门（G1/G2）、handoff 校验、最终交付
├── Sub agents: 负责阶段内分析/起草/审查
├── Phase 1: 主线程产出内容分析报告
├── Phase 2: 主线程产出 Web 演示母稿，G1 用户确认后冻结
├── Phase 3: 主线程调用 robot-aiot-arch-diagram 生成 flow/ 图表 SVG/HTML，G2 用户确认图表
├── Phase 3.5: 主线程回写图表产物路径与确认状态到母稿
└── Phase 4: 主线程委派 robot-aiot-interactive-html-author 逐页编写交互 HTML，合并单文件 / 产出 INDEX+pages
```

## 实战经验沉淀

1. 母稿是 Phase 4 的唯一内容源，母稿薄则页面必薄——内容厚度在 Phase 2 就要填满
2. 技术术语不按受众翻译，汇报版会立即失去可读性（技术同行受众除外）
3. 布局审查不是可选项，问题常常在页面 HTML 阶段才暴露
4. 视觉增强必须与布局分层，否则很容易破坏已验证布局
5. 主动合并内容重叠页面，通常比继续加页更有效
6. 右栏组件使用前先 grep 该页 CSS 是否含其定义，缺则随组件补丁一并插入
7. showcase 两页先行锁定风格基调，避免方向错误到全量完成才暴露
8. 步骤锚点特效（列表轮播+定格+图内节点联动）规范：li 自动轮播 `.on` 高亮（850ms/步、环尾停留 4200ms、首启 1600ms），click/Enter/Space 定格停播，图内对应节点同步 `.step-on` 发光（stroke 加粗+drop-shadow），节点 click 反向定位步骤，reduced-motion 只定格不轮播；配置驱动注入脚本 `_gen/inject_step_anchor.py`（幂等标记 `step-anchor-css`；li 来源支持 card+ci / all / liSel 三种）
9. 自动轮播与用户定位的滚动路径必须分离：`scrollIntoView` 只写在 show（用户 click/键盘触发），禁止写在 setOn（自动轮播调用），否则轮播拖动页面滚动条，演示观感崩坏
10. `[data-enter]` 入场动画 fill forwards 阶段在 Chrome 也生成 stacking context：卡内 z-index（浮层、badge）被困在卡的层叠上下文内无效，hover 浮层被 DOM 序靠后的邻卡遮挡；修复用 `.card:has(.cbadge:hover){position:relative;z-index:40}` 整卡抬升而非卡内加 z-index；定位手段为最小复现页多组并排对照（有/无动画 × 有/无修复），一张截图定案，不在成品页猜
11. 步骤列表 ↔ 图内节点映射必须按文案逐项对齐（节点内文本 vs li 文本语义匹配），禁止按位置顺序猜映射；图内无语义对应链时做纯轮播（nodes 空数组），不强行映射；映射表交付前用轮播态截图逐组复核
12. 图表全屏放大（`_gen/inject_chart_zoom.py`）规范：单击图内空白区放大铺满 stage、再击或 ESC 缩小；带 cursor:pointer 的交互节点不触发 zoom（避免点击语义冲突）；`#zoom` hash 直达放大态便于演示预定位
13. 轮播态验收法：headless Chrome `--virtual-time-budget` 取「首启 1600ms + n×850ms」时点截图，核对第 n 步 li 高亮与对应节点发光是否同组出现；比人工等待轮播可靠且可复现
