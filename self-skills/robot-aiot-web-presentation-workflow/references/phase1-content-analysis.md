# 内容分析规则

本文件定义 Phase 1 内容分析的执行规则。

## 输入

Markdown 知识文档，可能包含：
- 项目背景和目标
- 技术架构描述
- 业务指标和成果数据
- 流程图或架构图的文字描述
- 案例和实施细节

## 分析步骤

### 1. 提取汇报定位

从文档中识别或向用户确认：
- 汇报对象：集团领导 / 部门领导 / 技术团队 / 外部客户
- 汇报场景：年度总结 / 项目验收 / 方案评审 / 培训分享
- 核心诉求：争取资源 / 展示成果 / 对齐认知 / 推动决策

### 2. 识别核心信息

按以下维度分类提取：
- **结论类**：项目成果、业务价值、关键判断
- **数据类**：KPI、性能指标、对比数据、趋势数据
- **架构类**：系统组成、技术选型、部署拓扑
- **流程类**：业务流程、数据流、控制流
- **案例类**：典型场景、实施效果、用户反馈

### 3. 标记图表需求

对每条核心信息评估是否需要图表辅助：

| 信息类型 | 推荐图表 | 优先级 |
|----------|----------|--------|
| 系统组成 | 分层架构图 | 高 |
| 技术选型对比 | 表格或雷达图 | 中 |
| 业务流程 | 流程图 | 高 |
| 数据流 | 时序图或泳道图 | 中 |
| KPI 趋势 | 折线图或柱状图 | 高 |
| 占比分布 | 饼图或环形图 | 低 |
| 纯文字结论 | 无 | — |

### 4. 评估数据质量

对每个数据点检查：
- 是否有明确来源
- 是否为精确值还是估算值（估算值加 `~`）
- 是否可追溯到原始数据池
- 是否存在口径不一致风险

## 产物格式

```markdown
# 内容分析报告

## 汇报定位
- 对象：<...>
- 场景：<...>
- 核心诉求：<...>

## 核心信息清单
| 序号 | 信息摘要 | 类型 | 数据来源 | 备注 |
|------|----------|------|----------|------|
| 1    | ...      | 结论 | ...      | ...  |

## 图表需求列表
| 页面建议 | 图表类型 | 对应信息 | 优先级 |
|----------|----------|----------|--------|
| ...      | ...      | ...      | ...    |

## 数据质量备注
- <需要补充或确认的数据点>
```

## 阻塞条件

以下内容缺失时暂停并请求补充：
1. 汇报对象不明确
2. 核心结论无法从文档中提取
3. 关键数据无来源且无法估算
