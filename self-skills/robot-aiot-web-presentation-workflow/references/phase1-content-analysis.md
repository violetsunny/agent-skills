# 内容分析规则

本文件定义 Phase 1 内容分析的执行规则。

## 输入

Markdown 知识文档，可能包含：
- 项目背景和目标
- 技术架构描述
- 业务指标和成果数据
- 流程图或架构图的文字描述
- 案例和实施细节

## 分析步骤

### 1. 提取汇报定位

从文档中识别或向用户确认：
- 汇报对象：集团领导 / 部门领导 / 技术团队 / 外部客户
- 汇报场景：年度总结 / 项目验收 / 方案评审 / 培训分享
- 核心诉求：争取资源 / 展示成果 / 对齐认知 / 推动决策
- 结构形态：单文件 deck（默认）/ 多页形态（INDEX 总纲 + 每页上一页下一页导航）
- 输出目录：默认 `doc-web/`，用户可指定其他目录
- 页面规模：默认 5-15 页；用户明确要求扩充时记录扩充口径与理由

### 2. 识别核心信息

按以下维度分类提取：
- **结论类**：项目成果、业务价值、关键判断
- **数据类**：KPI、性能指标、对比数据、趋势数据
- **架构类**：系统组成、技术选型、部署拓扑
- **流程类**：业务流程、数据流、控制流
- **案例类**：典型场景、实施效果、用户反馈

### 3. 标记图表需求

对每条核心信息评估是否需要图表辅助：

| 信息类型 | 推荐图表 | 优先级 |
|----------|----------|--------|
| 系统组成 | 分层架构图（→架构图） | 高 |
| 技术选型对比 | 对比图（双栏/矩阵/四象限）或雷达图（→数据图） | 中 |
| 业务流程 | 流程图 | 高 |
| 数据流 | 时序图或泳道图 | 中 |
| KPI 趋势 | 折线图或柱状图（→数据图） | 高 |
| 占比分布 | 饼图或环形图（→数据图） | 低 |
| 部署位置/网络连接 | 拓扑图 | 高 |
| 问题↔价值/因果对应 | 映射图（含汇聚归因） | 中 |
| 多角色协作/双侧治理 | 泳道图 | 中 |
| 正向循环/飞轮机制 | 循环图 | 中 |
| 状态迁移/阶段演进 | 生命周期图（状态机/时间线/列演进） | 中 |
| 知识体系/概念放射 | 脑图（放射/树形） | 低 |
| 流量分合/多路分支 | 分流汇聚图（Sankey/分支流程） | 中 |
| 抽象层级/包含关系 | 层级图（层栈/嵌套/金字塔） | 中 |
| 纯文字结论 | 无 | — |

细分图名（折线图/雷达图等）括注所属大类，母稿标记以大类为准，避免触发 Phase 3 就近路由回补。

### 4. 评估数据质量

对每个数据点检查：
- 是否有明确来源
- 是否为精确值还是估算值（估算值加 `~`）
- 是否可追溯到原始数据池
- 是否存在口径不一致风险
- 厂商参考值/示例值必须标注，不得呈现为实测结论

### 5. 盘点既有资产

扫描输出目录（及用户指定目录）：
- 素材截图（平台界面、实拍图等）→ 产出素材图清单，供 Phase 2 做"图表 + 素材图并举"映射
- 品牌资产（Logo、既有页面配色 token）→ 有既有配色时直接沿用锁定全局主色
- 旧图表/旧页面 → 默认只作内容参考不直接复用；与新结构冲突时请用户确认归档或覆盖

## 阻塞条件

以下内容缺失时暂停并请求补充：
1. 汇报对象不明确
2. 核心结论无法从文档中提取
3. 关键数据无来源且无法估算
