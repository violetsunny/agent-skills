# 内容分析规则

本文件定义 Phase 1 内容分析的执行规则。

## 输入

用户指定的源文件（必需，未指定时先向用户索取，不得自行假设），以 Markdown 知识文档为主，可能包含：
- 项目背景和目标
- 技术架构描述
- 业务指标和成果数据
- 流程图或架构图的文字描述
- 案例和实施细节

PPTX 来源入口：用户给存量 `.pptx` 作内容源时，先跑 `scripts/extract_pptx.py`（agent 侧 python3 + python-pptx）提取 `extracted-slides.json`（逐页标题/正文/图片清单/演讲备注）与 `assets/` 图片落盘，经用户确认后并入本 Phase 分析——正文视同知识文档内容，演讲备注映射为 Phase 4 的 `.notes` 话术；提取脚本只做内容搬运，原版式取舍由用户在确认环节决定。

## 前置动作：交付格式确认

交付格式决定画布方向、文件结构与导航方式，必须在内容分析深入之前或与之并行敲定（本节是 SKILL.md Phase 1 入口约束条 2"一次性列齐反问清单批量确认（含交付形态）"细化出的前置动作），避免分析完成后才发现格式不匹配返工：

1. 格式枚举与选择判据：
   - **单文件 deck（默认）**：横版画布、翻页导航、单个 HTML 文件交付；用户无特殊说明时一律按此
   - **多页形态（INDEX + pages）**：`INDEX.html` 总纲 + `pages/` 逐页 HTML，每页带上一页/下一页控件、末页可返回 INDEX；用户要求逐页单独分发或逐页独立链接时选
   - **竖版社交 deck**：竖版画布（如 1080x1920，规格与用户确认）、保留翻页导航；移动端信息流、社交平台传播场景选
   - **滚动叙事页**：单页纵向滚动叙事，章节按"问题 → 方案 → 证明 → 行动"推进，无翻页；官网/落地页/长文讲解场景选
2. 确认方式：把格式枚举与默认值一次性列给用户，与"form 五问"同批确认（问题一次列齐、批量回答，不一来一回）；用户已在需求中指明时复述确认即可
3. 非默认格式的影响：多页形态文件结构见 SKILL.md"输出目录约定"；竖版社交 deck、滚动叙事页属非默认格式，画布方向、导航方式与视口规格须与用户确认后写入"汇报定位-结构形态"，随内容分析报告传给 Phase 4 作交付契约补充；纯原生零依赖、双击即用、`prefers-reduced-motion` 降级等硬约束对所有格式不变
4. 格式确认与内容分析可并行，但最迟在"### 3. 标记图表需求"前敲定——图表纵横比与信息密度受画布方向约束

## 分析步骤

### 1. 提取汇报定位：form 五问

五个问题全部回答完毕才进入后续步骤；能推断的先从文档推断并标注推断依据，推断不了的一次性列齐问用户批量回答。答案写入内容分析报告"汇报定位"节：

| # | 问题 | 判据 | 对后续 Phase 的影响 |
|---|------|------|---------------------|
| 1 | 受众是谁 | 领导层 / 技术同行 / 外部客户 / 大众；从文档汇报线与术语密度推断后向用户确认；未指定且无法推断时默认领导层 | 决定内容深度与术语密度（Phase 2 母稿"结论/话术"的写法）；与场景一起作 Phase 4 视觉风格选型输入 |
| 2 | 场景是什么 | 年度总结 / 项目验收 / 方案评审 / 培训分享；按文档类型与触发事件判断，判断不了问用户 | 决定叙事弧线与页面规模换算（Phase 2 分页）；决定能量曲线侧重（Phase 2 能量段位）；作 Phase 4 风格选型输入 |
| 3 | 核心主张 | 要让受众带走的一句话判断；必须能从结论类信息中提炼，提炼不出触发阻塞条件 | Phase 2 概览页围绕它组织、每页"结论"要素向它收敛；Phase 4 收尾峰页承载它的最终呈现 |
| 4 | 情绪基调 | 克制庄重 / 冷静理性 / 紧迫进取 / 庆祝性等；由受众+场景组合推断（验收→确定性证据感，评审→问题驱动张力，年度总结→庆祝与展望），用户明示偏好优先 | Phase 2 主题节奏（单色系内 hero 页密度）与能量曲线定调；Phase 4 视觉 mood 与色温、动效幅度 |
| 5 | 交付形态 | 默认单文件 deck，用户明确指定才改；枚举与确认方式见"前置动作：交付格式确认" | 决定文件结构、画布方向与导航方式（Phase 4 交付形态）；约束图表纵横比（Phase 3） |

五问之外的其余定位字段维持以下口径：
- 核心诉求：争取资源 / 展示成果 / 对齐认知 / 推动决策
- 汇报范围：源文件哪些章节/主题进 deck、哪些明确排除；从源文件结构推断后与五问同批向用户确认，范围外内容不得进入母稿
- 输出目录：默认 `doc-web/`，用户可指定其他目录
- 页面规模：默认 5-15 页；用户明确页数优先；用户明确要求扩充时记录扩充口径与理由

### 2. 识别核心信息

按以下维度分类提取：
- **结论类**：项目成果、业务价值、关键判断
- **数据类**：KPI、性能指标、对比数据、趋势数据
- **架构类**：系统组成、技术选型、部署拓扑
- **流程类**：业务流程、数据流、控制流
- **案例类**：典型场景、实施效果、用户反馈

### 3. 标记图表需求

对每条核心信息评估是否需要图表辅助：

| 信息类型 | 推荐图表 | 优先级 |
|----------|----------|--------|
| 系统组成 | 分层架构图（→架构图） | 高 |
| 技术选型对比 | 对比图（双栏/矩阵/四象限）或雷达图（→数据图） | 中 |
| 业务流程 | 流程图 | 高 |
| 数据流 | 时序图或泳道图 | 中 |
| KPI 趋势 | 折线图或柱状图（→数据图） | 高 |
| 占比分布 | 饼图或环形图（→数据图） | 低 |
| 部署位置/网络连接 | 拓扑图 | 高 |
| 问题↔价值/因果对应 | 映射图（含汇聚归因） | 中 |
| 多角色协作/双侧治理 | 泳道图 | 中 |
| 正向循环/飞轮机制 | 循环图 | 中 |
| 状态迁移/阶段演进 | 生命周期图（状态机/时间线/列演进） | 中 |
| 知识体系/概念放射 | 脑图（放射/树形） | 低 |
| 流量分合/多路分支 | 分流汇聚图（Sankey/分支流程） | 中 |
| 抽象层级/包含关系 | 层级图（层栈/嵌套/金字塔） | 中 |
| 纯文字结论 | 无 | — |

细分图名（折线图/雷达图等）括注所属大类，母稿标记以大类为准，避免触发 Phase 3 就近路由回补。

### 4. 评估数据质量

对每个数据点检查：
- 是否有明确来源
- 是否为精确值还是估算值（估算值加 `~`）
- 是否可追溯到原始数据池
- 是否存在口径不一致风险
- 厂商参考值/示例值必须标注，不得呈现为实测结论
- 涉及具体产品/技术/事件的存在性、发布状态、版本号、规格断言：第一步联网核实并固化成事实清单（落分析报告同目录），禁止凭训练语料断言；"我记得/应该还没发布/据我所知"句式禁入报告与母稿。该核实优先于澄清提问——查得到的先查，查不到的才问用户

### 5. 盘点既有资产

扫描输出目录（及用户指定目录）：
- 素材截图（平台界面、实拍图等）→ 产出素材图清单，供 Phase 2 做"图表 + 素材图并举"映射
- 品牌资产（Logo、既有页面配色 token）→ 有既有配色时直接沿用锁定全局主色
- 旧图表/旧页面 → 默认只作内容参考不直接复用；与新结构冲突时请用户确认归档或覆盖

## 产物格式

骨架模板：`templates/content-analysis-report.md`（复制到输出目录后逐节填充，占位符全部替换）。
五个章节固定：汇报定位 / 核心信息清单 / 图表需求列表 / 素材图清单 / 数据质量备注；字段口径见本文件"分析步骤"各节。

## 阻塞条件

以下内容缺失时暂停并请求补充：
1. 源文件未指定或未完整读取
2. 汇报对象不明确
3. 核心结论无法从文档中提取
4. 关键数据无来源且无法估算

阻塞项用户无回应时的出口（不枯等）：可合理推断的项（受众未指定默认领导层、场景按文档类型推断）按 best judgment 补齐，在报告中标注「假设：<内容>（未经用户确认）」后继续执行；无法推断的项（核心结论提不出、关键数据无来源）停在该项，先完成其余不受阻的分析，最后把待确认项一次性列给用户。

## 交接（handoff）

Phase 1 结束、进入 Phase 2 前执行交接：

- 本环节产物：内容分析报告（`<输出目录>/<内容分析报告>.md`，五章节齐备：汇报定位/核心信息清单/图表需求列表/素材图清单/数据质量备注）
- 下一环节输入：分析报告作 Phase 2 母稿编写依据（汇报定位定风格基调与受众表达、图表需求列表定图表清单、素材图清单定图文映射）
- 交接校验：`scripts/check_phase_handoff.py <输出目录> --phase 1 --write` → 校验分析报告存在 + 五章节齐备，落盘 `_gen/handoff-phase1.md`
- FAIL 阻塞：分析报告缺失或五章节不全，不得进入 Phase 2
