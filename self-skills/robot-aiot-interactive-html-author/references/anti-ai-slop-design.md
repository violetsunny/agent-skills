# 反AI模板感设计规则

## 定位

确保 Web 演示页面具有独特的视觉个性，避免千篇一律的 AI 生成感。

## 反AI slop 三默认（必须避开）

除非 brief 明确要求，否则禁止以下三种"安全牌"：

1. 暖奶油底 `#F4F1EA` + 衬线字体 + 赤陶色点缀
2. 近黑底 + 酸绿/朱红点缀
3. 报纸式排版 + 零圆角

## Lazy Defaults 清单

以下是选风格时的第一反应默认值，未经思考使用即 slop。内容确实需要时可以用，但必须能回答"为什么这页需要它"：

1. 渐变文字（`background-clip: text` 渐变大标题）
2. 左缘 accent 竖条卡片（`border-left: 4px` 彩条 + 浅底卡片）
3. 深底配青字/霓虹字、紫蓝渐变、霓虹辉光
4. 纯 `#000000` 底 / 纯 `#FFFFFF` 字（细则见 `premium-design-standards.md` 色彩纪律）
5. 等大卡片网格（细则见 `premium-design-standards.md` 布局纪律）
6. 全居中排版（细则见 `premium-design-standards.md` 反居中偏好）
7. 西文默认字体（禁用清单见 `premium-design-standards.md` 排版纪律）

目标是刻意选择，不是全面回避：品牌色就是紫蓝时照用，但须整套一致且有品牌理由。

**预设库例外**：用户从视觉风格预设库明确点名的深底霓虹 / 近黑酸色预设（studio、8-bit-orbit、pink-script 等）视为刻意选择，不以三默认或 Lazy Defaults 第 3 条拦截；前提是整套一致、不与其他预设混用、霓虹色不进正文（正文恒用可读文字色档）。

## data slop（无结论数字墙）

识别特征：

1. 页面堆满数字但没有一句结论——观众要自己在 KPI 墙里找重点
2. 指标卡每格都是"图标 + 大数字 + 一词标签"同构排版，数字无来源、无对比基线（同比 / 目标值 / 行业值三者全无）
3. 演示表格、示例曲线用假数据装点得花里胡哨，真实数据字段反而留白

规则：

1. 数据页标题即结论（主张句写法见 `web-slide-strategies.md` §Slide 写作硬约束第 1 条），数字是结论的证据不是装饰
2. 每个上屏数字必须能回答"来源 + 基线"，答不出就删
3. 无真实数据时留占位向用户要，不编造貌似合理的数值；占位必须假得明显（"待填"字样），不用逼真假值
4. 数字多时做主次分层：支撑结论的 1-3 个放大当主角，其余降为小字或移附录页
5. 自检问句：删掉这个数字，页面论证受损吗？不受损就删

## quote slop（金句滥用）

识别特征：

1. 编造的用户评价、名人名言当页面装饰
2. 大引用页连续出现，或每页一句"励志金句"，引文与该页论证无关
3. 署名模糊（"某用户"、"业内人士"）

规则：

1. 引文必须真实且署名具体（人名 + 身份 / 出处）；无真引文时留占位向用户要，不编造
2. 一个 deck 大引用页至多 1 页（预设页型配方本身是 quote 型的按其配方执行）；引文必须直接服务本页论证，装饰性引文一律删
3. 引文与 attribution 之间留白隔开，不贴在一起；引用页版式与主角轮换见 `web-slide-strategies.md` §视觉主角轮换
4. 替代方案：用真实用户数据、具体事实、前后对比替换装饰性引文——具体事实的说服力大于任何金句

## bento 用烂

识别特征：

1. 三个等大卡片横排——最典型签名，无论内容是否恰好三条、是否并列
2. 格子数 ≠ 内容条目数：4 条内容硬塞 6 格，空格用装饰填或干脆空着
3. 每格同构"图标 + 标题 + 一句话"，无大小 / 跨列 / 内容形态差异
4. 页面有空隙就上格子，而不是内容本身是并列结构

规则：

1. 仅在两个条件同时成立时用 bento：内容本身是并列结构 + 条目数恰好填满格子；任一不满足改列表 / 表格 / 时间线
2. 用则卡片必须不等大：大小差异化、有的跨列、有的带图有的纯文字（等大卡片网格禁令细则见 `premium-design-standards.md` 布局纪律与本文 Lazy Defaults 第 5 条）
3. 空格子不用装饰填——内容少一条就少一格或换版式；填充物即 filler，删
4. 图标不是每格必需：图标滥用让页面玩具化，纯文字格完全合法

## CSS 神器过度清单

以下技巧用对位置是神器，被无差别铺开就是最易识别的生成痕迹。审查时逐项过：

| 技巧 | 过度识别特征 | 替代 |
|---|---|---|
| 磨砂玻璃 `backdrop-filter` | 整页卡片全磨砂；实底背景上也加 blur（底下无内容可透，模糊无对象）；磨砂上文字对比度 < 4.5:1 | 实色 surface + 1px 发丝边框；磨砂只给真正有内容从底下经过的浮层（sticky 导航 / 模态），每页至多 1-2 处 |
| 渐变 | 全屏多色相渐变背景；渐变文字 + 渐变边框 + 渐变底同页；渐变色相与品牌色无关 | 实色块 + 明度阶梯（单一主色推导见 `visual-style-presets.md` §单一主色推导三步法）；渐变文字禁令见本文 Lazy Defaults 第 1 条与 `premium-design-standards.md` 色彩纪律 |
| 阴影 | 全元素 blur > 40px 且透明度 > 0.3 的重阴影；多层彩色 glow；平面风页面靠重阴影制造层级 | 层级用色块邻接 / 发丝线 / 留白表达；锁定预设"字体·形状"行写"阴影无"时全套零阴影（见 `visual-style-presets.md` 条目） |
| 圆角 | 同页圆角档混用（4/12/20/28px 齐上）；> 24px 非 pill 的中间档；圆角与锁定预设圆角档冲突 | 全 deck 跟随锁定预设的圆角档与 corners 旋钮（见 `visual-style-presets.md` §3 主题五维旋钮）；每页圆角档 ≤ 2 档 |

通用判据：觉得"加一下会更好看"时，那通常就是过度使用的征兆——先做最简版本，技巧只在关键位置出现一次胜过全页铺开。

## 背景层配方

背景层机制（常驻 `#bg` + 透明内容层）见 `interactive-html-authoring.md` 共享背景层一节；本节只管背景层里放什么：

1. radial glow：品牌色相大径向光晕，透明度 ≤15%，偏心放置
2. ghost text：超大号低透明度文字作纹理，3-8%，不得与前景争可读性
3. hairline grid：1px 发丝线网格或横纹，透明度 ≤10%
4. grain：噪点纹理（SVG `feTurbulence` 或预生成 data URI），透明度 ≤5%，防大面积实底死平
5. 主题装饰：与内容主题直接相关的线稿装饰（电路走线、等高线、工具轮廓抽象化）

约束：每个场景选 2-5 个，不全堆；所有背景元素共享一个呼吸律动（同周期、同缓动的 ambient 动画，编排护栏见 `keyframe-animation.md`）；背景层不参与内容转场，只做慢速 ambient。

## OKLCH 单色相派色板

用户只给一个品牌色、需要派生整套色板时，在 OKLCH 空间派生，不手挑 hex：

1. 锁定色相 H（品牌 hue），L 从 95% 到 15% 走 5-7 档生成明度阶梯
2. 同 L 档下 C 越高越鲜艳（强调用）、越低越灰（次级元素用）
3. 暗底取低 L 高 C 档作 accent；浅底取高 L 低 C 档作 surface
4. CSS 直接写 `oklch(L% C H)`；导出环境不兼容时转 hex 固化进 token
5. 派生色板色温天然一致，避免手挑混色显脏

已有成套品牌规范时以规范为准，不派生。

## 两遍工作流

### 第一遍：设计计划

动手写代码前先输出设计计划：

1. **Token 系统**：4-6 hex 色值 + 2+ 字体角色 + 布局概念 + signature 元素
2. **自检独特性**：这个设计方案能否在 10 个同类页面中被一眼认出？
3. **Subject-grounded**：设计选择来自产品/主题自身的材料/工具/人工制品/通俗语言

### 第二遍：实现

确认设计计划通过自检后再写代码。

## Typography 承载个性

- display + body 刻意配对，不用同一字族的不同权重凑数
- type scale 有意设定权重/宽度/间距，不做等比缩放
- 中文场景：标题用思源黑体/阿里巴巴普惠体 Heavy，正文用思源黑体 Regular

## Structure = Information

- 编号/分隔/标签必须编码内容的真实结构，非装饰
- 列表层级反映信息从属关系，不是视觉偏好

## Motion 审慎

- 一个编排好的时刻胜过散落效果
- 有时少即是多：如果不确定是否需要动画，就不加

## Signature 元素

- boldness 花在一处，其余安静纪律
- 每页最多一个视觉焦点，其他元素保持克制

## Copywriting 规范

- 用户视角命名："保存更改"不说"提交"
- 主动语态，控制感
- 错误消息不道歉不含糊，直接说怎么修
- sentence case，无 filler 词

## CSS Specificity 警告

避免类选择器与元素选择器互相取消。优先使用单一层级的类名体系。

## 反例隔离容器

任务本身要展示反设计（讲"什么是 slop"、新旧对比评测页）时，反例必须装进诚实的 bad-sample 容器，让反例服务叙事而不污染页面主调：

- 虚线边框（如 `2px dashed`）+ 角标"反例 · 不要这样做"
- 反例容器内的 slop 元素不进入页面视觉基调统计（accent 单区、活跃元素 ≤3 等按正例区计）
- 同页正反对照时，正例与反例容器等宽等高，差异只留给被对比的属性

## 伪 chrome 禁令

画面内容区禁止绘制装饰性假 player UI（假进度条、假时间码、假版权署名条）：

- 与 deck 真实 chrome（进度条/页码/`.stage-hud`）撞车，观众无法分辨哪个是真的，属 slop
- 进度与时间只交给真实外壳承载（真实进度条、真实计时器，见 `presenter-mode.md`）
- 演示素材截图里自带的产品 UI 不在此列——那是内容，不是 chrome
