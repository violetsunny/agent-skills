# 内容AI图像生成与信息图

## 定位

为 Web 演示页面生成内容配图、信息图和社交媒体风格的可视化卡片，增强信息的视觉传达力。

## 内容配图规则

### 何时需要配图

1. 抽象概念需要具象化（如"边缘计算"→设备+云的示意图）
2. 数据关系需要空间表达（如对比、流程、层级）
3. 纯文字段落超过 5 行且包含可视觉化的信息
4. 页面需要视觉节奏变化（打破纯文字的单调感）

### 配图风格选择

| 内容类型 | 推荐风格 | 说明 |
|---------|---------|------|
| 技术架构 | 等距/扁平图标 | 与架构图风格一致 |
| 数据对比 | 信息图卡片 | 大数字+标签+趋势 |
| 流程说明 | 步骤图/时间线 | 编号+图标+简述 |
| 概念解释 | 隐喻插图 | 用日常事物类比 |
| 案例展示 | 场景图/截图 | 真实或模拟的使用场景 |

| 数据类型 | 推荐布局 |
|---------|---------|

| 多指标对比 | Dashboard Grid / Comparison Bar |

## 社交媒体图片样式（小红书/微信风格）

当演示需要导出为社交分享图时：

### 12种预设样式

Cover / Carousel / Quote / Data Card / Checklist / Tutorial / Comparison / Timeline / Profile / Event / Product / Minimal

### 尺寸规范

- 小红书：1080×1440（3:4）或 1080×1080（1:1）
- 微信公众号封面：900×383（2.35:1）
- 朋友圈：1080×1080（1:1）

### 竖版 deck 画布（小红书图文/轮播形态）

用户明确要求以社交图文形态交付时，deck 整体可用竖版画布：

1. 画布固定 `810x1080`（3:4），与小红书 `1080×1440` 导出规格同比，出图按 4/3 线性放大（headless 截图 `--window-size=810,1080 --force-device-scale-factor=1.3333`）
2. 这是 `interactive-html-authoring.md` 画布约束 `1920x1080` 的唯一竖版例外：安全边距、不重叠不溢出、scale-to-fit 壳全部照常适用，壳的缩放分母改为 `810/1080`
3. 竖版页单列纵向流、大字上对齐、页码点作翻页指示；不把 1920 宽的双栏/网格布局硬压进竖版画布

### 配色方案

支持 3 种 palette 预设 + 自定义，确保与演示主色一致。

## 衍生交付形态规格（文档 PDF A4 / 落地页 1440px）

仅用户点名对应交付形态时适用；deck（1920×1080）与竖版社交 deck（810×1080）不受本节影响，本节不改变"约束"任何条款。

### 文档形态 PDF（白皮书 / 报告 / 打印资料）：A4

1. 页面规格：A4 纵向 210×297mm（595×842pt）；CSS 写 `@page { size: A4; margin: 18mm 16mm; }`，页眉/页脚/页码放安全区内，跨页统一设计
2. 边界：本规格只管文档形态 PDF 交付；deck 打印导出仍按 `interactive-html-authoring.md`"打印与导出"执行（`@page` 1920×1080、一页一张），两种形态不混用
3. 长文阅读版式：正文栏宽约 32 个中文字符（≈66 拉丁字符），中文行高、段间距等细则按 `typography.md` §5.5 执行，不重述；图表块写 `break-inside: avoid` 防跨页截断
4. 诚实性照常：图表程序化画真实值，截图走"真图诚实性测试"与"截图取景与合成规范"；封面页与章节导航属文档设计，本文件不展开

### 落地页 / 产品官网形态：1440px

1. 设计基准宽 1440px（Desktop），首屏高度 100vh，首屏内传达核心价值与主 CTA；响应式断点向下覆盖至 320px
2. 该形态豁免 deck 画布"固定 1920×1080 不响应式"约束（`interactive-html-authoring.md` 画布约束条 1 只管 deck 与竖版社交 deck），允许响应式断点；滚动叙事结构（问题 → 方案 → 证明 → 行动）按落地页通用结构展开，本文件只锁尺寸规格
3. 首屏配图与信息图照常执行本文件配图规则与真图诚实性测试；社交分享图衍生用"社交媒体图片样式"尺寸规范表

## AI 图像生成集成

### Provider 优先级

Google → OpenAI → Azure → OpenRouter → DashScope → Z.AI → MiniMax → Replicate → Jimeng → Seedream → Agnes

codex-cli 永不自动选择。

### 使用边界

- AI 生图仅用于氛围/背景/隐喻插图
- 数据图表必须程序化生成，不用 AI
- prompt 不含文字，文案后期叠加
- 用户未要求时不主动使用

## 无 API Key 降级策略

当环境中未配置任何图像生成 API Key 时：

1. **不阻塞主流程** — AI 图像生成是可选增强能力，缺失时自动降级
2. **配图降级为 SVG/CSS 构建** — 用内联 SVG 图标、CSS 渐变、几何图形组合替代 AI 插图
3. **信息图保持程序化** — 信息图本身即为 HTML/CSS/SVG 构建，不受影响
4. **提示用户** — 输出 `[NO-AI-IMAGE] 未检测到图像生成 API Key，配图已降级为 SVG/CSS 构建`
5. **不尝试调用外部服务** — 跳过 AI 生图步骤，直接使用程序化方案

检测方式：检查环境变量中是否存在以下任一 Key：`GEMINI_API_KEY`、`OPENAI_API_KEY`、`AZURE_OPENAI_API_KEY`、`DASHSCOPE_API_KEY`、`MINIMAX_API_KEY`、`REPLICATE_API_TOKEN`。全部缺失即触发降级。

## 约束

1. 配图服务于内容理解，不是装饰
2. 信息图数据必须来自 Phase 1 数据池，可溯源
3. 社交图片是演示的衍生输出，不是主要交付物；竖版 3:4 社交 deck 例外——该形态下 deck 本身即交付物
4. 所有配图需通过高级感审查（`premium-review-fix.md`）
5. 无 API Key 时必须降级，不得虚构生成结果或静默跳过

## 真图诚实性测试（真实截图 vs 程序化合成 vs AI 生成）

"截图取景与合成规范"与"AI 图像生成集成 · 使用边界"的前置门：任何声称呈现"真实产品 / 真实数据"的图，动手前按序回答三问，任一"否"即按对应列处置，不跳过：

| # | 问题 | 是 | 否 |
|---|---|---|---|
| 1 | 有无真实数据源？图中数字、图表、UI 内容来自 Phase 1 数据池或用户提供的真实系统输出 | 按真实值画 | 禁止伪造精确数字：占位数据显式标"示意"（SKILL.md 硬约束 6），或向用户索取真实数据 |
| 2 | 能否取到真图？用户实截、可访问的真实系统截图、官方素材视频截帧 | 必须用真实截图，程序化合成优先（下节"截图取景与合成规范"）；禁止凭记忆印象重画真实 UI | 取不到真图才允许程序化合成或 AI 情景图，且在交付说明中声明"合成示意" |
| 3 | 合成是否误导？观众会不会把合成/生成图当成真实产品界面或真实数据 | 不构成误导，可用：抽象概念图、隐喻插图、氛围图、已标"示意"的示意图 | 构成误导：加"示意 / 合成"标注或改抽象图示表达；逼真实 UI 形态 + 逼真数据表且无标注 = 以假充真，禁止 |

补充纪律：

1. 真实 UI 从真实上下文长出：用户给了 codebase / 设计 token / 产品 URL 时，先读取精确值（色值、间距、组件形态）再画；能取到真实截图时绝不手搓（与 `ui-demo-choreography.md` §2 制作规范一致，不重述）
2. 无任何真实上下文时，明确告知用户"产出为合成示意，非真实产品界面"，不默默硬上——与"无 API Key 降级策略"条 4 的失败可见同一原则
3. 真实品牌 logo 不出现在合成与 AI 生成图中（"AI 图像生成集成 · 使用边界"与"通用规则"的假 logo 禁令已有，此条是其在诚实性维度的应用）
4. before/after 对比的 before 用真实旧态（`ui-demo-choreography.md` §3 式⑤），不手搓故意丑的假 before——与问 3 同源
5. 三问先行决定"用真图 / 程序化合成 / AI 生成"，再进下节取景 7 参数流程；三问不改变"数据图表必须程序化生成"的既有结论，只增加"无真实值时标示意"的出口

## 截图取景与合成规范（真实产品截图进 deck）

用户提供的产品截图、网页截图、代码截图、设计稿截图进 deck，首选**程序化合成**：创建目标槽位比例的画布，铺统一风格背景，把原截图等比缩放放入——内容、文字、UI 细节保真，不重画。AI 生图只做"截图再设计 / UI 情景图"：原图过长、过窄、信息太乱或需要概念化情景表达时才用。

### 处理链路

1. 先匹配版式：确定页面登记版式与图片槽位比例（S22 顶图 21:9、S15/S16 图片格统一 21:9 或 16:10、M 系左文右图 16:10/4:3、M05 网格 281px 定高）
2. 再选处理方式：保真 → 程序化合成；统一视觉不改内容 → 合成 + 主题背景；原图不可用或需解释概念 → AI 再设计
3. 再选背景：同一 deck 用同一套背景风格，预生成后复用，不每张截图临时生成
4. 最后合成：背景 cover 铺满目标比例画布，截图等比缩放后按 `padding` 与 `alignment` 放入

默认不裁掉截图内容；只有图片已按槽位比例重新生成、或用户明确允许裁切时才用 cover 裁切。

### 开始前澄清（用户可能提供截图时）

- 截图位置与类型（网页 / App / 代码 / dashboard / 设计稿）
- 处理目标：保真展示 / 统一美化 / 重新设计成 UI 情景图 / 混合
- 目标槽位与比例；是否必须保留全部文字数据；是否需遮盖账号、头像、项目名等敏感信息
- 构图居中、贴角还是按内容自动判断

### 取景 7 参数

每张截图处理前先确定：

| 参数 | 可选值 | 判断方式 |
|---|---|---|
| `ratio` | 21:9 / 16:10 / 16:9 / 4:3 / 1:1 | 跟随版式图片槽位，不跟随原截图比例 |
| `background` | plain / gradient / wallpaper / blurred / grid / paper | 跟随 deck 风格系与主题 |
| `padding` | compact / standard / spacious | 普通截图 standard；文字密集或高图 spacious；小图组 compact |
| `inset` | none / subtle / balanced | 截图需从背景中浮出用 balanced；S 系多用 none/subtle |
| `shadow` | none / soft / editorial | M 系可 soft/editorial；S 系默认 none |
| `corners` | square / small / medium | S 系 square；M 系 small/medium |
| `alignment` | center / top-left / top-right / bottom-left / bottom-right | 跟随页面构图，不永远居中 |

### 风格映射（对应登记版式两系）

**M 系杂志风**：背景 paper / blurred / 低饱和 gradient；纸张、墨水、胶片颗粒、暖白、低对比质感；截图可小圆角 + 轻微阴影，但不做成 SaaS 营销卡片。推荐语义：

```text
ratio:16:10, background:paper, padding:standard, inset:balanced, shadow:editorial, corners:small, alignment:center
```

**S 系瑞士风**：背景 plain / grid / dot-matrix；accent 只允许极低占比，无大面积亮色块；截图直角、无阴影、无圆角，少量 hairline 或顶部 accent 线。推荐语义：

```text
ratio:21:9, background:grid, padding:standard, inset:subtle, shadow:none, corners:square, alignment:center
```

### 背景强度规则

截图背景是托底，不是主视觉：

1. `alignment` 不确定时，背景中心与四角都必须安静；截图放某角时该角不得有强色块
2. accent 只做 5%-8% 视觉占比的淡线、点阵或极浅几何场；禁高亮色条、大色块、霓虹渐变
3. 背景不得含文字、logo、图标、人物、设备、边框、明显主体或方向性构图
4. 背景必须 crop-safe：裁成 21:9 / 16:10 / 4:3 / 1:1 都不暴露被裁痕迹
5. 背景资产按 1920×1080 级 16:9 预生成后程序化 cover 裁到各槽位；新增背景资产用本节末尾提示词生成，常规合成不实时生成

### 截图类型决策

| 原始素材 | 推荐处理 |
|---|---|
| 普通网页 / App / 桌面截图 | 程序化合成到目标比例 |
| 产品 UI 细节重要 | 程序化合成 + contain，不重画 |
| 长网页截图 | 截关键区域或拆 2-3 张同尺寸面板（同组同高度档） |
| 极窄 / 极高截图 | 先试 spacious + 侧向 alignment；仍太小再 AI 再设计 |
| 代码截图 | M 系纸感背景；S 系浅网格背景；文字必须可读 |
| 概念解释用 UI 情景图 | AI 再设计（类型 6 / 瑞士 3 模板） |

### 标注叠加规则

1. 截图标注（编号角标、短标签、区域框选）一律用 HTML/SVG 叠加层做在截图上方，不画进 AI 生成图，不烧进截图像素
2. 标注只用 accent 色 + 单色 hairline；编号角标用直角小方块 + mono 数字，标签 ≤8 字
3. 标注层不得遮挡截图关键文字与数据；标注超过 3 处时改用"截图 + 侧列说明卡"版式（S08 / M04）

### 背景生成提示词（仅新增背景资产时）

M 系：

```text
16:9 crop-safe screenshot background for an editorial magazine / e-ink presentation system. Warm off-white paper texture, subtle ink wash, fine film grain, low contrast, quiet center and quiet corners, no text, no logo, no objects, no border, no focal subject. Suitable for cropping to 21:9, 16:10, 4:3, or 1:1.
```

S 系：

```text
16:9 crop-safe screenshot background for a Swiss International Style presentation system. Pure off-white base, ultra-subtle 16-column grid and sparse dot matrix, one accent color only: [theme accent], used at very low opacity as thin lines or tiny dots, no large bright color blocks. Quiet center and quiet corners, no text, no logo, no objects, no border, no focal subject. Suitable for cropping to 21:9, 16:10, 4:3, or 1:1.
```

## 配图 AI 生成 Prompt 模板

### 使用边界（先读）

1. 信息承载类图（信息图、流程图、关系图、数据图）默认程序化 SVG/HTML 构建——走上方"信息图布局（21种）"与图表能力；AI 生图默认只做氛围照片、隐喻插图、UI 情景图，与本文件"AI 图像生成集成 · 使用边界"一致
2. 仅当用户明确要求"整图 AI 生成"时，才使用信息承载类模板（类型 2-5/7 与瑞士 2/5）；此时图内文字必须短标签，并在 prompt 中指定语言
3. 走 AI 生图时下方通用规则与后缀约束必带

### 通用规则

- 先判定 deck 风格系：M 系 = 电子杂志 × 电子墨水；S 系 = 瑞士国际主义（12/16 列网格、无衬线气质、单一高饱和 accent、直角纯色、发丝线、极大留白）
- 图内文字语言跟随 deck 语言：中文 deck 用中文，英文 deck 用英文
- 不生成卡通、3D、霓虹科技感、SaaS 模板感、过度装饰、假 logo
- 给标题/正文留可叠加空间，不满屏堆细节；同组图必须同比例、同视觉缩放、同边距密度
- 配图是嵌入素材不是独立页面：不生成页眉、页脚、页码、标题栏、角标、署名、装饰边框等页面外壳
- 生成图落 `images/`，命名 `{页号}-{语义}.{ext}`，不外链

### 比例 → 槽位

| 用途 | 比例 | 槽位 |
|---|---|---|
| 章节封面 / 全屏主视觉 | 16:9 | M 系 hero 背景 |
| S 系顶部横幅 / 图片主视觉 | 21:9 | S22 顶图（648px 全幅） |
| 左文右图主图 | 16:10 或 4:3 | M04 / M10 右列 |
| 信息图 / 系统关系图 | 16:9 或 16:10 | 原始素材 contain；按槽位重生成则 cover 铺满 |
| 截图再设计 / UI 情景图 | 16:10 或 21:9 | 同上 |
| 图文混排小图 | 3:2 或 3:4 | M10 右列 |
| 多图网格 | 统一横图 | S15/S16 图片格或 M05 网格（同组同高） |

### 后缀约束（每张必带）

```text
输出必须是[16:9/16:10/4:3/3:2]横向构图，主体居中但保留边距，画面密度中等，与同组图片保持相同视觉缩放和边距。只保留核心图形/画面本身，不要生成页眉、页脚、标题、页码、角标、署名、装饰边框、超长条、竖图或不规则比例。
```

同页多图时追加：

```text
这是一组图片中的一张，请保持与同组图片相同的画面比例、元素大小、边距、线条粗细和标注密度。
```

### M 系模板（类型 1-7）

**类型 1 · 人文纪实照片**（现场感、真实世界锚点）：

```text
生成一张横向纪实摄影配图，主题是：[页面概念]。经典胶片纪实摄影质感：自然光、低饱和、轻微颗粒、真实工作或生活现场，克制有人文温度。适合电子杂志 × 电子墨水风格页面，留出标题空间。不要商业摆拍、科幻界面、AI 机器人、logo 或水印。[接后缀约束]
```

**类型 2 · 杂志风信息图**（概念/流程/关系解释；默认程序化构建，见使用边界）：

```text
生成一张横向杂志风信息图，解释：[概念/流程/关系]。电子墨水风格，黑白灰为主，少量低饱和强调色，细线条、网格、编号、短标签、留白充足。图中文字使用[中文/英文]，保持简短可读。不要卡通、3D、霓虹科技感或模板感。[接后缀约束]
```

**类型 3 · 流程 / Pipeline 图**：

```text
生成一张横向流程信息图，展示：[步骤 1] → [步骤 2] → [步骤 3] → [结果]。电子杂志 × 电子墨水风格，细箭头、分段编号、短注释、克制留白。图中文字使用[中文/英文]。只保留核心流程图本身，不要页面外壳。比例：16:9。
```

## 原生 SVG 静态地图（S08 地理插槽实现细则）

地点、街区、路线、城市关系、门店/校区/事件点位、人物住所关系内容，用 S08 地理插槽（登记见 `swiss-layout-system.md` S08 条目）：左列说明卡 + 右列原生 SVG 静态地图。不引外部地图库与瓦片服务，不做滚轮缩放/拖动交互（防误触 deck 翻页），不设地图控制按钮。

### 数据契约

写页面前先定义点位与关系：

```js
const MAP_POINTS = [
  { id: 'a', name: '点位A', meta: '总部', coord: [117.2048, 39.1060], x: 62, y: 68, accent: true },
  { id: 'b', name: '点位B', meta: '研发中心', coord: [117.1988, 39.1080], x: 34, y: 48 },
  { id: 'c', name: '点位C', meta: '工厂', coord: [117.2028, 39.1090], x: 52, y: 54, side: 'left' },
];
const MAP_RELATIONS = [['a', 'b'], ['b', 'c']];  // 无序连线：空间/关系牵连
const MAP_ROUTE = ['a', 'c', 'b'];                // 可选：有序路线，渲染为折线
```

字段约定：`id` 唯一标识；`name` 点位名（标签卡标题）；`meta` 短标签（≤8 字，mono）；`coord` [经度, 纬度]（换算源数据）；`x/y` 面板内百分比坐标（0-100，渲染用）；`accent: true` 强调点（accent 色）；`side: 'left'` 标签卡翻到点左侧（近右缘的点用）。

### 经纬度 → 百分比坐标换算

只给 `coord` 时按包围盒线性投影（城市级范围精度足够）：

1. 取全部点位包围盒 lngMin/lngMax/latMin/latMax
2. 预留贴边余量 p=12（百分点），逐点计算：
   - `x = p + (lng - lngMin) / (lngMax - lngMin) * (100 - 2p)`
   - `y = p + (latMax - lat) / (latMax - latMin) * (100 - 2p)`（纬度反转，北在上）
3. 退化情形：单点或某维跨度为 0 → 该维取 50 居中
4. 跨省域尺度时 x 轴先乘 cos(中心纬度) 压缩横向跨度再投影，避免东西向拉伸
5. 换算结果写回数据契约 `x/y`，渲染阶段不再触碰经纬度；标签卡避让需要时允许对单点手调 ±5 百分点

### 渲染规则（1920×1080 画布锚定，写 px）

1. 面板结构：右列地图面板（直角、浅灰底、overflow hidden），高度与左列卡片堆总高对齐；左列 = 头卡（accent 底反白短句 + 一行说明）+ 2-4 张关系解释卡
2. SVG 层只画几何：viewBox 写面板实际 px（如 `viewBox="0 0 1080 660"`），坐标 = 百分比 × 面板宽(高) / 100；禁 `<text>`（锁定机制第 4 条）
3. 连线：1-2px 虚线（stroke-dasharray 4 3）、accent 色、opacity 0.6-0.7；`MAP_ROUTE` 折线同样式并加箭头 marker 表方向
4. 点与引线画在 SVG：点用 10×10 直角方块点（与 S 系直角语言一致；如需圆点语义可用 12px 圆点 + 2px 纸白描边，全图统一一种）；ink 色，accent 点用 accent 色；引线 1px 水平线约 24px，默认从点向右伸出，`side:'left'` 向左
5. 标签卡是 HTML：绝对定位，锚点 = 引线末端（点百分比坐标换算 px 后偏移），`translate` 垂直居中；卡 = 点名 + meta 短标签（mono 大写），纸白底、1px hairline 描边、直角、无阴影
6. 避让：标签卡互不重叠、不遮其他点、不压面板左上标题块；近右缘点用 `side:'left'` 翻转；自动排布失败时手调该点 x/y
7. 底图质感（可选）：2-3 条极淡直线（opacity ≤0.11）暗示街道/河流，或纯浅灰底；不画真实瓦片，不伪造真实地理细节

### 与 S08 的衔接与动效

1. `<section>` 仍写 `data-layout="S08"`，不新增版式编号；页面结构 = 顶部标题 + 左说明卡 + 右地图面板
2. 动效沿用 S08 镜像入场语义：连线 stroke-dashoffset 描线 → 点依序 pop → 标签卡淡入；reduced-motion 时全部静态直出
3. 左列关系卡不惜字：每卡完整一句 2-3 行，讲清两点为什么相关，不只写标签

### 视觉检查

- 左列卡片总高与右列地图面板对齐，不上浮一半
- 面板标题块与标签卡不互相遮挡
- 标签卡至少显示点位名，meta 只作短标签
- 全部点位落在面板安全区内（12% 余量），不贴边
