# Web 演示布局策略与文案公式

## 定位

为交互式 Web 演示提供页面布局模式和文案组织框架，供页面编写与母稿分页时选型。

## 25种布局模式

| 页面类型 | 推荐布局 | 核心结构 |
|---------|---------|---------|
| 封面 | Title | 大标题+副标题+品牌标识 |
| 问题陈述 | Problem | 痛点数字+影响描述 |
| 解决方案 | Solution | 方案概述+核心价值 |
| 功能展示 | Feature Grid | 2x2/3x2网格 |
| 数据看板 | Metrics Dashboard | 3-4个大数字+趋势 |
| 对比分析 | Comparison | 双栏/表格 |
| 时间线 | Timeline | 水平节点+里程碑 |
| 图文分栏 | Split | 左文右图或上文下图 |
| 关键数字 | Big Number | 单个大数字+上下文 |
| 引用/证言 | Quote | 大字引用+来源 |
| 行动号召 | CTA | 明确指令+联系方式 |

## Slide 写作硬约束

1. **标题是完整句子主张，不是标签**：写"中小仓库每周花 14 小时人工盘点"，不写"盘点问题"——标题脱离配图也能独立成立
2. **一页一想法一视觉**：想加第二组要点或第二张图时，拆页
3. **punchline 前置**：最强论点放 deck 前部、页面首位；观众从左上方读到右下方，然后停止
4. **测算必须给算式**：自下而上构建（客户数 × 客单价、请求量 × 转化率），禁止无算式的"500 亿市场"
5. **字号按演示形态分档**：演讲/大屏投影——观众必读文字 ≥ 40px、标题 72-96px；桌面阅读/信息密集汇报——维持全局约束正文 ≥ 16px。两档按受众场景选择，不混用、不互相覆盖
6. **hero 页大标题锚定 180-240px**：1920×1080 画布下，hero 页（封面/幕封/问题页/大引用/收尾，主题档定义见 §登记版式主题节奏（全 deck 单色系））大标题用 180-240px——三行长题取 180-200px 档、一行短题取 220-240px 档，断行断在语义处；正文页标题仍走第 5 条 72-96px 档，两档不互串。中文巨字字距归零、行高 1.15-1.25，拉丁巨字可收至 −0.04em、行高 0.9-0.94（细则见 `typography.md`）；巨字只用字重档表达分量，字重不足时不用 text-shadow 伪加粗

## 密度模式二分

字号分档之外同时锁定密度模式，两档二选一不混用：

| 模式 | 页面纪律 | 正文下限 | 预设示例 |
|---|---|---|---|
| **演讲型** | 每页 ≤1 焦点、单页填充 ≤50%、chrome 可隐 | ≥40px（大屏） | grove, vellum, studio, pink-script, monochrome, signal, soft-editorial |
| **阅读型** | 网格填满、账本行 / 高密度表格允许、信息极大化 | ≥16px | neo-grid-bold, retro-windows, stencil-tablet, scatterbrain, raw-grid, sakura-chroma |

1. 封面与收尾页恒为演讲型，无论正文页选哪档
2. 每套预设的密度档见 `visual-style-presets.md` 条目"字体·形状"行；预设密度档与内容密度需求冲突时摆出冲突让用户裁决，不平摊
3. 中密度预设（多数）两档皆可，选定后全 deck 锁定

## 双语（中英混排）Deck 规则

标题需中英双语或 deck 含大量英文术语时启用：

1. **`<html>` 声明 `lang="zh-CN"`**：浏览器与读屏器按此选择中英混排渲染策略；英文为主的页面改 `lang="en"`，中文段落局部标 `lang="zh-CN"`
2. **双语标题上下堆叠，不左右并排**：中文主标题在上、英文副题在下——`<h1>主标题<br><span class="subtitle-en">English Subtitle</span></h1>`；并排在演示级字号下折行不可控
3. **英文副题降视觉权重**：字重低于主标题（主标题 700+ 时副题 ≤ 400），颜色走 `--text-secondary` 或主文本色降不透明度，不与中文主标题抢视觉
4. **混排字体栈双字形覆盖**：沿用全局系统栈（`"PingFang SC","Microsoft YaHei",system-ui,sans-serif`），拉丁字符由系统回落拉丁字体；不为双语 deck 外链字体，不内嵌两套 webfont

## 交互版特有规则

1. 布局选择考虑翻页节奏，每页信息量均匀
2. 文案公式适配"一屏一结论"原则
3. 数据动效配合文案节奏，先出结论再展开细节
4. 过渡动画服务于叙事连贯性，不是装饰

## 登记版式主题节奏（全 deck 单色系）

适用：S/M 登记版式 deck（见 `swiss-layout-system.md`）；其余单文件 deck 可参照做节奏规划。M 系每页 `<section>` 必带主题四档之一：light / dark / hero light / hero dark；**全 deck 单色系**——要么全 light 系（light + hero light），要么全 dark 系（dark + hero dark），禁止 light/dark 两系混排交替；色系在母稿阶段选定，写页时不得改档。hero 档用于章节封面/开场/收束/转场，非 hero 档承载正文。S 系以纸白底为主，页内节奏由 ink 反转块与 accent 满屏页制造。

节奏硬规则（生成后自检）：

1. 全 deck 单色系：主题档只允许同一色系的普通档 + hero 档，混入另一色系即 FAIL
2. 8 页以上 deck 必须至少 1 个 hero 档（与本 deck 色系同系）
3. hero 页落章节交界（封面/幕封/问题页/大引用/收尾），不连续超过 2 页 hero
4. 呼吸节奏靠 hero 档与非 hero 档交替、版式骨架轮换与能量段位制造，不靠明暗翻面
5. 先画节奏对齐表再动手写 slide；跳过规划直接粘骨架 = 全是普通档无 hero

版式主题默认值（light 系 deck；dark 系 deck 将 light→dark、hero light→hero dark 镜像映射）：

| 版式 | 默认主题 | 原因 |
|---|---|---|
| M01 开场封面 | hero light | 开场定场，色系内最高档 |
| M02 章节幕封 | hero light | 章节交界呼吸点 |
| M03 数据大字报 | light | 数字需纸白底 |
| M04 左文右图 / M10 图文混排 | light | 正文主力 |
| M05 图片网格 | light | 截图需亮底 |
| M06 流水线 | light | 流程图需清晰 |
| M07 问题页 | hero light | 章节内强调点 |
| M08 大引用 | light | 金句靠排版分量不靠翻面 |
| M09 对比页 | light | 双列需清晰 |
| S01 封面 / S10 收尾 | accent 满屏 / 左半 accent + 右半纸白 | 首尾色彩闭环 |
| S 系正文 | 纸白底为主 | ink 块（S03/S12/S13）作页内节奏 |

8 页节奏模板（light 系，可直接套用；dark 系整表镜像）：

| 页 | 主题 | 版式 | 备注 |
|---|---|---|---|
| 1 | hero light | 封面 | 开场 |
| 2 | light | 大字报 | 数据抛出 |
| 3 | light | 左文右图 | 对比/故事 |
| 4 | light | 流水线 | 流程 |
| 5 | hero light | 章节幕封 | 呼吸 |
| 6 | light | 左文右图或大引用 | — |
| 7 | hero light | 问题页 | 悬念收束 |
| 8 | light | 大引用/结尾 | 收尾 |

## 视觉主角轮换

主题节奏（单色系内 hero 档与普通档）管底色呼吸，本节管每页视觉焦点的元素类型与位置轮换。每页都是"居中大标题 + 下方一张图"当主角时，档位再轮换也还是模板。

主角类型轮换表（按页面内容选类型，相邻页不同类型）：

| 主角类型 | 适用页 |
|---|---|
| 巨字排版（文字本身当主角） | 封面 / 幕封 / 问题页 / 收尾 |
| 单大图 / 产品截图 + 设备框 | 功能展示 / 实例页 |
| 大数字（单 KPI 占屏） | 关键数字页 |
| 图表（条形 / 折线 / 环形） | 数据论证页 |
| 时间轴 / 流程轴 | 演进 / 流程页 |
| 对比卡（前后对照 + 中轴） | 对比分析页 |
| 引文大字 + 落款 | 证言 / 金句页（引文真实性纪律见 `anti-ai-slop-design.md` §quote slop） |
| 不等大卡片格 | 功能并列页（滥用纪律见 `anti-ai-slop-design.md` §bento 用烂） |

轮换硬规则（生成后自检）：

1. 位置轮换：画布分四象限 + 中心共 5 个位置，视觉主角重心不得连续 3 页落在同一位置——连续两页主角在左上，第三页必须换位
2. 类型轮换：同一主角类型至多连续 2 页；连续两页"大数字"后第三页换图或换排版主角
3. 构图轮换：满版 / 全居中构图至多连续 1 页，随后必须用非对称构图（左文右图 / 对角分割 / 侧栏）打破
4. 规划先行：写代码前把"页码 → 主角类型 → 主角位置"登记表与主题节奏表（§登记版式主题节奏（全 deck 单色系）第 5 条）一起列出，审查时两表逐页对照
5. 登记版式例外：S/M 登记版式页的视觉主角由版式编号固有结构决定（如 S03 分屏、M03 大字报），轮换靠版式选型切换实现，不改动登记版式的内部结构

## 登记版式封面与收底

1. S 系默认色彩闭环：封面 S01 accent 满屏（可选 ASCII 字符呼吸场背景，实现与生命周期见 `generative-art-and-canvas.md`），收尾 S10 左半 accent + 右半纸白 takeaway——"开场全 accent ↔ 收尾半 accent"
2. 收尾右侧第 3 条 takeaway 用 accent 强调，把 accent 色从左半穿到右半完成缝合
3. 反白大标题 weight 200；强调字拉丁用 italic+300、中文降级字重/颜色——accent 压 accent 看不见（见 `typography.md` 第二节）
4. 封面不再放大编号（页眉已有页码）；收尾每 deck 仅 1 页，不得出现在中间页
5. 封面没用 accent 满屏时，收尾改用经典 ink 双半屏变体，保持首尾重量对称

## chrome 与 kicker 分工

1. 页眉 chrome 左上 = 栏目/导航元数据：稳定的"栏目名"或"章节分类"，跨多页可以相同（"Act II · Workflow" / "Data · Result"）
2. 页眉 chrome 右上 = 页码 + 幕号，固定格式（"Act II · 15 / 25"）
3. kicker = 本页独一份的引导句，是大标题的"小前缀"（像杂志大标题上方的一行话），每页都应不同、短句有戏剧性（"BUT" / "一个人，做了什么。"）
4. chrome 与 kicker 禁止写同一句话或互相翻译——chrome 是栏目标签（稳定可复用），kicker 是本页钩子（每页独一份），互为补充；重复会一眼露出 AI 生成痕迹

结构位置：kicker 必须在大标题上方（flex column 上下叠，gap 15px），禁止 grid 两列挤成左右（见 `swiss-layout-system.md` P0 结构对齐）。

## 底部导航安全区（nav-safe）

适用：登记版式 deck；其余含底部分页圆点的单文件 deck 同样适用。

1. 分页圆点固定 bottom 22px，视觉占据约 1004px 之后区域；主内容、图片 caption、图表说明、timeline label 的最低处必须停在安全区上方
2. 登记版式统一预留底部 86px 安全区；底对齐图片版式已内置安全区，不要再额外把图片或 caption 往页面底部推
3. 手写 `align-items:end` / `margin-top:auto` / `position:absolute;bottom` 的页面必须目检：内容最低边缘与分页圆点之间 ≥32px 呼吸；横向时间线要同时检查上下 label 与安全区

## 登记版式飞行前检查

1. 版式先登记：每页写代码前列"页码 → data-layout → 为什么选它 → 图片槽位"，`data-layout` 必须是登记编号（S01-S25 / M01-M10）
2. 主题节奏先行：先画 light/dark/hero 分布表（对照 8 页模板），再动手写 slide
3. 字号下限对照：必读档 ≥40px（演讲型）、任何文字 18/16/14px 底限、中文大标题分档（见 `typography.md`）
4. 结构对齐：水平 padding 不二次叠加（画布卡已带左右 96px，主体 `padding:0`）、kicker 在大标题上方、子块间距用 grid gap 不用 margin 堆
5. 组件必选/可选边界：页眉与 kicker 在 head 区必选（正文卡片内可省 kicker）；大标题在章节/论点页必选，列表型小卡页可用较小标题但不能缺页级信息锚点；lead 可选——标题已解释清楚可省，但不用长段正文贴着标题；图片 caption 在 S15/S16 多图格必选、S22 可选；hairline 只用于建立层级不为装饰堆线；KPI 数字只在有真实数据时使用；脚注可选但必须避开 nav-safe

生成后审查按 `premium-review-fix.md` 流程执行；登记版式额外视觉锚点：大标题保持轻字重、留白不填满到底、hairline 只在章节边界/证据墙/卡片层级处、timeline label 不碰安全区、每页不误用其他版式的组件（如无真实数值的概念列表套数据图表）。

## 教学/课程场景元素

教学模块、在线课程、工作坊讲义启用；商务汇报不加，避免侧栏与自测抢内容权重：

1. **常驻学习目标侧栏**：左侧窄栏（画布宽 18-22%）列本节学习目标，随翻页高亮当前目标，目标 ≤ 5 条；侧栏为 slide 同级常驻 chrome（做法同 `interactive-html-authoring.md` 共享背景层模式），正文区让出对应宽度，不被侧栏压住
2. **MCQ 自测页**：每个知识点小节结束插一页单选自测——题干 + 3-4 选项，点击选项即时反馈（正确：高亮 + 一句解析；错误：降暗 + 显示正确答案），纯原生 JS 实现；选项点击属可交互内容，翻页点击热区不得覆盖；自测页不计入叙事页数预算
3. **目标与自测呼应**：每道自测题对应侧栏一条目标，答对后该目标标记完成（对勾）
