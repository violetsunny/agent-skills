# Slide HTML 编写规则

本文件定义领导汇报类单页 HTML 的内容组织、设计 token、轻量规范化边界和交付审查方式。
其中设计系统标准已直接重写在本文件中；`ui-ux-pro-max` 作为运行时能力依赖，用于设计系统建议和审查，不作为这里的规范真源。

## 母稿原则

1. 先明确“说什么”，再决定“怎么摆”
2. 页面只承载一个主题，不把多个结论塞进同一页
3. 上屏内容服务决策，不展示实现噪音

## 每页四要素

```markdown
## 第 N 页：<页面标题>

### 标题
> <一句话定位>

### 页面结论
> <一句话结论>

### 页面上屏内容
<图表 / 表格 / 关键数字 / 流程 / 案例>

### 汇报话术
- <解释业务意义、风险、动作>
```

话术承载规则：

1. 话术只写给演讲者，解释变化、归因和动作，不复述屏幕上已有的文字
2. 交付的页面 HTML 中，话术写入画布内 `<div class="notes">`（`display:none`），随页面一起交付，结构见 `slide-page-template.md` 第 8 节
3. 演讲者专用文字（提示语、口播稿、"这一页讲……"类描述）一律进 `.notes`，禁止以任何可见元素出现在页面上

## 内容规则

1. 数据先行，话术负责解释变化、归因和动作
2. 每个关键数字尽量补一个业务价值锚点
3. 架构图、流程图等视觉页仍要补 2-3 个数字或结论锚点
4. 流程表达优先用“准备 → 执行 → 治理”闭环
5. 页面中避免直接出现表名、类名、Topic 名、内部 API 路径

## 内化后的设计系统

本技能把适合领导汇报页的设计系统标准直接重写为一套页面语言；同时在执行时可调用 `ui-ux-pro-max` 提供设计系统建议、反模式提醒和可读性审查。

### 1. 信息层级

1. 标题承担导航作用，结论承担判断作用，图表承担证据作用
2. 主数字和核心结论必须形成第一眼扫描路径
3. 次要解释、注释和来源信息保持退后，不与结论抢视觉权重

### 2. 语义色系统

页面推荐至少定义：

1. `--primary-color`：核心主色，默认服从首页架构图主色
2. `--on-primary-color`：主色填充上的文字色，按 WCAG AA 对主色实测选白或近黑；其余强调色/状态色同理配对 `--on-*-color`
3. `--secondary-color`：次级强调色
4. `--tertiary-color`：补充分类色
5. `--bg-color`：画布外 body 底色，与 surface 分层
6. `--surface-color` / `--surface-muted`：容器背景
7. `--outline-color`：边界和分割
8. `--text-primary` / `--text-secondary` / `--text-tertiary`：正文、辅助文本与最低档注记文本

规则：

1. 主色负责最重要的结构线、重点数字、标题强调
2. 强调色/状态色填充上的文字只用配对 `--on-*-color`，禁止硬编码 `#fff` / `#000`
3. 容器层次优先通过 surface 明暗差表达，不靠重阴影堆层次
4. 状态色只在确有含义时使用，不把红绿橙滥用成装饰色

### 3. 字级体系

推荐映射：

1. `Display`：封面核心标题、极少数年度/总数大字
2. `Headline`：页面主标题、一级区块标题
3. `Title`：卡片标题、分栏标题
4. `Body`：正文解释、图表说明、列表内容
5. `Label`：标签、徽章、脚注、页码

中文字体栈优先：

```css
font-family: "PingFang SC", "Microsoft YaHei", sans-serif;
```

规则：

1. 标题优先靠字重和留白拉开层级，不靠过度放大
2. 正文默认 `16-20px`
3. 标签和脚注默认 `12-14px`
4. 行高通常保持在 `1.3-1.6`

### 4. 间距与圆角

1. 间距主尺度：`8 / 16 / 24 / 32 / 48px`
2. 常用圆角：`8 / 12 / 16 / 24px`
3. 胶囊按钮、标签、徽章可使用 `9999px`
4. 卡片内边距一般不低于 `14px`

### 5. 层次与质感

1. 默认使用实色背景、轻渐变或轻阴影
2. 只有在用户明确要求时才使用毛玻璃或重模糊
3. 任何视觉增强都不能破坏数据区和图表区的阅读稳定性

### 6. 可访问性与稳定性

1. 不只靠颜色表达差异，必要时加标题、图例、趋势词
2. 不依赖 hover 才能看到关键信息
3. 文本与背景必须保持足够对比
4. 装饰图形不能压住标题、结论、关键数字或 Logo

## 轻量规范化边界

这里的规范化是页面壳层治理，不是重做图表或重做产品界面。

允许：

1. 统一背景、容器、标题层级、圆角和间距基线
2. 统一页面 token 和语义色角色
3. 统一结论区、数字区、图表区、说明区的视觉节奏

不允许：

1. 改图表节点坐标、结构、数据映射、颜色语义
2. 把图表页重做成另一套应用 dashboard
3. 为了追求风格而牺牲事实表达和领导可读性

## 配色冲突处理

当页面推荐主色与首页架构图主色冲突时：

1. 首页架构图主色覆盖 `--primary-color`
2. 推荐主色降级为 `secondary` 或 `tertiary`
3. 字级、间距、容器层次规则继续保留

## 页面生成步骤

1. 读取母稿与页面类型
2. 先加载 `ui-ux-pro-max`，拿到页面级设计系统建议与反模式提醒
3. 再选布局骨架，按本文件内化规则补 token 变量
4. 再放标题、结论、图表、数据卡、说明、页脚；图表类产物（XML/SVG/图表 HTML）位于输出目录 `flow/` 子目录，页面 HTML 落 `pages/`，页面引用图表用 `../flow/<图表名>.html` 相对路径
5. 最后补轻量视觉增强
6. 生成后按模板清单逐项审查，并用 `ui-ux-pro-max` 做一次页面质量复核

## CSS 分层

1. 基础层：画布、尺寸、绝对定位、间距、对齐
2. 语义层：颜色变量、字级变量、容器角色
3. 增强层：渐变、阴影、圆角胶囊、强调描边

基础层画布壳约束：

1. `1920x1080` 设计画布外必须包一层 scale-to-fit 视口自适应壳：浏览器任意窗口尺寸下画布等比缩放居中、无滚动条完整可见；`1920x1080` 视口时 scale=1，headless 截图与下游消费不受影响
2. 标准实现：

```html
<div class="fit-viewport"><div class="canvas">…</div></div>
<script>
(function(){var c=document.querySelector('.canvas');function fit(){var s=Math.min(innerWidth/1920,innerHeight/1080);c.style.transform='scale('+s+')';}addEventListener('resize',fit);fit();})();
</script>
```

```css
html,body{height:100%;overflow:hidden}
.fit-viewport{height:100vh;display:flex;align-items:center;justify-content:center}
.canvas{transform-origin:center center}
```

增强层约束：

1. 不改 `position`、`top`、`left`、`width`、`height`
2. 去掉增强层后，基础布局仍应成立
3. 视觉增强出问题时，优先删增强层而不是重写基础层
