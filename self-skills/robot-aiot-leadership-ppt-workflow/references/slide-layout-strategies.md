# PPT 页面布局策略与文案公式

## 定位

为汇报 PPT（目标受众由用户指定，默认领导层）提供策略性布局模式和文案公式，增强页面的说服力和信息传达效率。本规则补充 `robot-aiot-draw-flowchart` 的静态页面 HTML 能力，专注于内容策略层。

## 17种核心布局模式

按页面类型选择对应布局：

| 页面类型 | 推荐布局 | 核心结构 |
|---------|---------|---------|
| 封面 | Title | 大标题+副标题+品牌标识，居中或左对齐 |
| 问题陈述 | Problem | 痛点数字+影响描述+紧迫感 |
| 解决方案 | Solution | 方案概述+核心价值+差异化 |
| 功能展示 | Feature Grid | 2x2/3x2网格，图标+标题+一句话 |
| 数据看板 | Metrics Dashboard | 3-4个大数字+趋势箭头+标签 |
| 对比分析 | Comparison | 双栏/表格，Before/After或竞品对比 |
| 利弊权衡 | Pros-Cons | 左右利/弊卡片+底部权衡结论，用于方案取舍页 |
| 变更对照 | Diff | 改造前后两版对照+变化点高亮，用于优化/迁移成果页 |
| 时间线 | Timeline | 水平/垂直节点，里程碑+关键事件 |
| 路线图 | Roadmap | NOW/NEXT/LATER分栏卡片，每栏≤4条；精确排期改引甘特图真源 |
| 团队介绍 | Team | 头像+姓名+角色+一句话贡献 |
| 引用/证言 | Quote | 大字引用+来源+背景图 |
| 图文分栏 | Split | 左文右图或上文下图，50/50或60/40 |
| 关键数字 | Big Number | 单个大数字+上下文说明+趋势 |
| 截图展示 | Screenshot | 设备框+标注+说明文字 |
| 定价/方案 | Pricing | 2-3列卡片，推荐项高亮 |
| 行动号召 | CTA | 明确指令+联系方式+截止时间 |

## 11种核心Deck策略

按汇报场景选择叙事弧线：

| 策略 | 适用场景 | Emotion Arc |
|------|---------|-------------|
| YC Seed | 融资路演 | 问题→方案→市场→团队→Ask |
| Guy Kawasaki | 产品发布 | 10/20/30法则 |
| Series A | 成长期融资 | Traction→Vision→Plan |
| Product Demo | 产品演示 | 痛点→Demo→价值→下一步 |
| Sales Pitch | 销售提案 | 客户问题→方案→ROI→案例 |
| Duarte Sparkline | 变革推动 | What Is ↔ What Could Be交替 |
| QBR | 季度回顾 | 成果→差距→计划→资源 |
| All-Hands | 全员大会 | 愿景→进展→挑战→号召 |
| Conference | 技术分享 | Hook→故事→洞察→ takeaway |
| Workshop | 培训研讨 | 目标→概念→练习→总结 |
| Case Study | 案例分享 | 背景→挑战→方案→结果 |

### Duarte Sparkline 详解

What Is ↔ What Could Be 交替推进，在 1/3 和 2/3 位置打破模式制造转折。适用于需要推动变革或说服决策的场景。

### Deck 级硬规则

1. **相邻两页不得使用相同布局模式**（可校验硬规则；母稿排页后逐对检查布局列）。同一布局整套复用时至少间隔 2 页
2. 叙事骨架基线：封面 → 目录 → 章节过渡 → 每章 2-4 页正文 → 收束结论 → 致谢/行动号召。页数 ≥ 10 时目录页与章节过渡页必配，< 10 时可省目录
3. 演讲时长按页数换算：30 分钟 = 8-12 页，45 分钟 = 12-16 页，1 小时 = 16-22 页；用户给了时长没给页数时按此推荐并确认

## PPT 风格精选（8 种）

风格是整套 deck 的视觉语法（底色节奏、字体配对、信息密度、装饰克制），布局模式（17 种）是单页骨架。执行顺序：先按本节锁定风格，再逐页选布局；文案组织与话术写作不受风格影响，仍按"8个核心文案公式"与"话术（逐字稿）写作三铁律"执行。

与 `slide-premium-design.md` 的层级关系：三档风格基调（A 克制商务 / B 深底科技 / C 暖调编辑）是受众映射的基线，本节 8 种风格是基调框架下的具体语法选型；选定后仍须整组落成 token 覆盖集，且不得与受众→基调映射冲突（领导层默认 A，禁用 B 除非品牌主色即深色系）。

两条不随风格改变的纪律：

1. 主色语义以首页架构图/品牌资产为准（`--color-primary`），风格只规定版式、字体配对、密度与装饰元素的语法，不改主色
2. 静态交付约束：任何风格不得引入动画与交互（ppt-master 只消费静态 HTML），本文件"动画类"一节仅在交互版产物中使用

### 8 种风格

| 风格 | 视觉特征 | 适用汇报场景 | 与 17 种布局的衔接 |
|---|---|---|---|
| 咨询双字体版 | 衬线展示标题 × 无衬线正文的高对比配对；深蓝×白二元色 + 单一品牌色高亮；左上角结论式整句标题；细线 pattern 装饰；暖灰底留白 | 高管业务汇报、行业研究、权威机构提案——领导层默认场景中最正式的一档 | 结论式标题与四要素契约"标题即结论"天然一致；Problem/Solution/Comparison/Pros-Cons 主场；大数字卡接 Big Number、Metrics Dashboard |
| 断言-证据版 | 整句结论标题（非名词短语）；标题下独占一张证据图；零 bullet；白/极浅灰底 + 单一克制强调色；高数据墨水比 | 技术评审、工程汇报、数据严谨型决策页 | 与四要素"标题/结论/上屏内容"一一对应；证据图槽位直接引用 `flow/` 图表 HTML；Big Number、Split、Metrics Dashboard 主场；零 bullet 纪律倒逼上屏内容精简 |
| 机构极简版 | 纯白底黑灰字 + 单一品牌强调色；顶部标题带 + 下方多栏对仗；2×2 矩阵；一页一信息、留白充分 | 立项/投资决策路演、标准商业提案、问题-解法叙事 | 17 布局中兼容面最广：Comparison（2×2 竞品矩阵）、Feature Grid、Roadmap、Pricing 均零冲突；首页架构图主色即唯一强调色时色彩冲突最小 |
| 便当格模块版 | 浅灰/奶白底；不等高圆角卡片网格 + 微描边或微阴影；超大展示标题与常规正文强字重对比；KPI 数字表格体；每卡一个洞见 | 产品能力汇总、QBR 指标页、成果汇报页 | Feature Grid、Metrics Dashboard 主场；须遵守布局纪律"bento 格子数=内容条目数"与"禁三个等大卡片横排"（KPI 等大指标卡豁免）；卡内 sparkline 用内联 SVG，静态版不引 Chart.js（见本文件 Chart.js 边界声明） |
| 大字报数字版 | 白底或近黑底 + 单一高饱和强调色；巨型数字占半屏（tabular-nums 收紧字距）；章节页大色块单词；严格基线网格 | 年度复盘、QBR 业务回顾、里程碑成果页——需要用一个数字制造记忆点的场景 | Big Number 的放大形态；章节过渡页用大色块（对应 Deck 级硬规则 2 的叙事骨架）；数字必须来自 Phase 1 数据池，估算值显式加 `~` |
| 图谱箭头企业版 | 企业色块 + 产品线分色；箭头流程、分层架构盒、图标化能力网格；流程即叙事；清晰无衬线 | 平台架构讲解、客户旅程、方法论流程、生态地图——机器人/AIoT 架构类汇报的主场 | 直接消费 Phase 3.5 图表 HTML（`flow/` 目录），页面风格只做外框与结论层，不得重绘图表真源；Solution、Timeline、Roadmap、Feature Grid 适配 |
| 暗色舞台版 | 近黑底（非纯黑）灰白字（非纯白）；一屏一词或一个巨型数字；单一品牌强调色高亮；大量负空间 | 产品发布、全员大会、愿景页——现场大屏演讲场景 | Title、Quote、Big Number、CTA 主场；高信息密度页（Metrics Dashboard、Comparison）不适合此语法；领导层受众默认禁 B 基调——仅品牌主色即深色系或用户点名时，用作章节过渡/愿景页的局部节奏页，不作整套风格 |
| 杂志编辑版 | 奶油/米白纸感底；阅读级衬线排版；刊头 + 眉标的出版物页面语法；内联数据卡穿插散文节奏；超大展示数字锚点 | 年度信/复盘叙事、对外品牌刊物、供传阅阅读的汇报册——非讲台演示默认 | Quote、Split、Big Number 接内联数据卡；对应 C 暖调编辑基调；唯一允许放宽眉标的风格（见下方"眉标边界"） |

### 场景→风格路由

与 11 种 Deck 策略配合选择；用户未指定风格时按本表推荐 2-3 种，经两页 showcase 门定稿（见 `phase4-page-authoring.md`）：

| 汇报场景（Deck 策略） | 首选 | 备选 |
|---|---|---|
| 融资路演（YC Seed / Series A） | 机构极简版 | 咨询双字体版 |
| 业务汇报 / QBR | 咨询双字体版 | 大字报数字版 |
| 产品发布（Product Demo / Guy Kawasaki） | 便当格模块版 | 暗色舞台版（发布会现场） |
| 技术评审 / 技术分享（Conference） | 断言-证据版 | 图谱箭头企业版 |
| 架构 / 平台汇报 | 图谱箭头企业版 | 断言-证据版 |
| 变革推动（Duarte Sparkline） | 断言-证据版 | 大字报数字版 |
| 全员大会（All-Hands） | 暗色舞台版 | 大字报数字版 |
| 案例分享（Case Study） | 杂志编辑版 | 咨询双字体版 |
| 复盘 / 年度总结 | 杂志编辑版 | 大字报数字版 |

### 风格硬规则

1. 整套锁定一种风格，禁止混用或中途更换（与 `slide-premium-design.md` §3 基调锁定规则同源）；风格与基调必须一致，选定后一并落成 token 覆盖集
2. 风格选型结果写入设计解读行与母稿头部，随两页 showcase 门一并确认（见 `phase4-page-authoring.md`）
3. 字体落地遵守 `slide-premium-design.md` §4 排版纪律：中文字体栈 + 全套最多两个字体族；不得为风格引入无法确认渲染环境的字体，离线渲染掉字时退回默认字体栈
4. 风格不豁免 Deck 级硬规则：相邻两页布局不同、同一版式家族重复限制等仍逐页检查

### 眉标边界

眉标 = 标题上方的全大写小标签（eyebrow）。PPT 语境裁决：

1. **领导汇报 PPT 维持眉标克制**：沿用高级感设计标准 §4 条 7"全大写小标签（eyebrow）整套汇报最多每 3 页出现 1 次；多数页面标题本身足够，不需要眉标"（PPT 静态路径真源为 `robot-aiot-draw-flowchart` 的 `slide-premium-design.md`，交互路径 `premium-design-standards.md` 同条）。本节 8 种风格中除杂志编辑版外，全部执行此上限，不放宽。
2. **杂志编辑版（出版物风）可放宽，须注记场景**：出版物 grammar 的刊头 + 眉标是页面骨架而非装饰，允许每页固定眉标（章节标签）。必须同时满足两个条件：① 设计解读行与母稿头部注记本套场景为"出版物/册子传阅阅读"，非讲台演示；② 眉标只承载章节语义（如"第二章 · 平台能力"），不得出现编号眉标（"01 / 概览"一类，AI 痕迹清单第 1 条，恒禁）、版本号页脚与装饰性分隔（破折号/中点串禁令照旧）。
3. **审查衔接**：眉标超量按 `slide-premium-review.md` 检查清单作阻塞项处理；杂志编辑版放宽生效时，审查同步核对场景注记与章节语义两个条件，缺一即按超量判定。

## 话术（逐字稿）写作三铁律

母稿"汇报话术"栏与页面 HTML `.notes` 容器中的话术，按以下规则写作：

### 铁律 1：是提示信号，不是念稿

1. 核心关键词加 `<strong>` 强调，扫一眼能接上，不写成连贯长文
2. 过渡句独立成段（每段 1-3 句），段间即呼吸点
3. 结尾自然引出下一页

### 铁律 2：每页 150-300 字

1. 少于 150 字提示不够，讲到一半会卡
2. 多于 300 字来不及扫完，等于没写
3. 对应 2-3 分钟/页的汇报节奏

### 铁律 3：用口语，不用书面语

| 书面语 | 口语 |
|---|---|
| 因此 | 所以 |
| 该方案 | 这个方案 |
| 然而 | 但是 / 不过 |
| 进行优化 | 优化一下 |
| 我们将会 | 我们会 / 接下来 |
| 综上所述 | 删掉，直接说结论 |

写完读一遍，听起来像说话才算过。

### 话术不上屏（显式禁止）

话术只存在于母稿话术栏和页面 HTML 的 `.notes` 容器（`display:none`）；任何提示语、口播稿、"这一页讲……"类描述出现在页面可见区域，即违反四要素契约，审查按阻塞项处理。

### 批量生成 prompt 模板

让 AI 为整套 deck 批量生成逐字稿时直接使用 `templates/notes-prompt.md` 中的 prompt 全文（内容即三铁律的 prompt 化，生成后仍按三铁律逐条验收），不得凭记忆转抄。

## 8个核心文案公式

按slide类型映射：

| 公式 | 适用 | 结构 |
|------|-----|------|
| PAS | 问题页 | Problem → Agitate → Solution |
| AIDA | 封面/CTA | Attention → Interest → Desire → Action |
| FAB | 功能页 | Feature → Advantage → Benefit |
| Cost of Inaction | 紧迫页 | 不做的代价量化 |
| Before-After-Bridge | 对比页 | 现状 → 理想 → 桥梁 |
| 3W | 结论页 | What → So What → Now What |
| STAR | 案例页 | Situation → Task → Action → Result |
| SPIN | 需求页 | Situation → Problem → Implication → Need-payoff |

## Chart.js 集成规则

> 边界声明：本节 Chart.js 仅适用于本技能的交互版产物（PPT 静态版仍用 SVG/HTML 图表）；`robot-aiot-interactive-html-author` 的单文件 deck 执行零外部依赖硬约束，图表一律内联 SVG/CSS 手绘，不得引入 Chart.js。两者产物形态不同，规则不互通。

当页面需要交互式数据图表时：

- `responsive: true` + `maintainAspectRatio: false`
- 暗色主题：grid `rgba(255,255,255,0.1)`，ticks `#9ca3af`
- 亮色主题：grid `rgba(0,0,0,0.08)`，ticks `#6b7280`
- 动画时长 ≤ 1s，避免干扰阅读

## CSS变量体系

```css
--color-primary: /* 主色，来自首页架构图 */
--color-background: /* 页面背景 */
--color-secondary: /* 辅助色 */
--primitive-gradient-primary: /* 主渐变 */
--typography-font-heading: /* 标题字体 */
--typography-font-body: /* 正文字体 */
```

## 动画类

| 类名 | 效果 | 适用 |
|------|-----|------|
| animate-fade-up | 向上淡入 | 通用入场 |
| animate-stagger | 依次延迟入场 | 列表/网格 |
| animate-scale | 缩放进入 | 数字/图标 |
| animate-count | 数字滚动 | 关键指标 |
| animate-pulse | 脉冲呼吸 | 状态指示 |

## 约束

1. 布局选择服务于内容结论，不为炫技选复杂布局
2. 文案公式是思维框架不是填空模板，必须填入真实数据
3. 动画仅在 ppt-master 支持时使用，静态 HTML 阶段不加动效
4. Chart.js 仅在交互版使用，PPT 静态版用 SVG/HTML 图表
