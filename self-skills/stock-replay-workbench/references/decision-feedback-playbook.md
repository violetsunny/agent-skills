# Decision Feedback Playbook（复盘四分类 + 决策绩效闭环）

## 适用场景

对历史操作建议/持仓决策做事后评估、计算胜率、迭代策略时使用。配合 `replay_builder.py` 与 `.analysis/` 历史报告。

## 一、复盘四分类

每条历史决策（买入/卖出/持有建议）在 N 个交易日后（默认 N=5，可配 10/20）结算为四类之一：

| 分类 | 定义 | 含义 |
|---|---|---|
| TRUE_POSITIVE | 建议方向与后续走势一致（看多且跑赢基准，看空/减仓且回避了下跌） | 决策正确 |
| FALSE_POSITIVE | 建议方向与后续走势相反 | 决策错误，需归因 |
| MISSED_OPPORTUNITY | 未给建议/建议观望，但标的随后出现显著行情（如 5 日涨幅 ≥ 15% 或触及关键位） | 漏判，检查筛选条件是否过严 |
| REGIME_MISMATCH | 决策逻辑本身自洽，但市场阶段判断错误（如 CAUTION 期建议加仓后遇系统性下跌） | 归因到 regime 层而非个股层 |

### 方向正确率口径

- 看多建议：标的收益 **跑赢基准**（默认沪深300 或所属板块指数）才算正确，绝对上涨不算。
- 看空/减仓建议：标的跑输基准或绝对下跌才算正确。
- Hold/观望建议：**不计入**方向正确率分母，单独统计 MISSED_OPPORTUNITY 率。

### 归因要求

FALSE_POSITIVE 与 REGIME_MISMATCH 必须写归因，至少覆盖：

1. 数据层：输入数据是否缺失/滞后（对照 `missing_data` 记录）。
2. 信号层：信号本身是否成立但被更强信号覆盖。
3. regime 层：派发日级别/情绪阶段判断是否错误。

## 二、决策绩效闭环

### 结算流程

1. 从 `.analysis/` 报告或建议记录中提取决策条目（标的、方向、日期、理由摘要）。
2. 用 `quote_history`（带 `as_of` 防未来函数）取决策日与结算日价格。
3. 按四分类打标，累计到绩效表。
4. 每类错误达到阈值时触发规则修订（见下）。

### 评级单调性自检

若建议带强度分级（如 强烈推荐 > 推荐 > 观察），结算后必须验证：

- 各级别的方向正确率应单调递减。
- 出现倒挂（观察级胜率 > 推荐级）说明分级标准失效，需重新校准或废弃分级。

### 最小样本晋升标准

- 任何策略/信号在样本 < 20 条时，绩效数字只作参考，不得写入 SKILL.md 或用于调整默认参数。
- 样本 ≥ 20 且方向正确率显著高于基准（如 +10pp 以上）才可晋升为默认规则。
- 连续 10 条样本正确率 < 40% 的规则应降级或停用。

### 防未来函数

- 结算取数一律走 `as_of` 参数（`quote-history`/`chip-distribution`/`distribution-days`/`stock-diagnose` 支持），禁止用结算日之后的数据评估决策日。
- `stock-diagnose` 传入历史 `as_of` 时自动附 `snapshot_notice`（实时类接口无法回溯的警示），报告中保留该声明；其他子命令不会自动附加，需要时手动引用。

## 三、输出格式

绩效报告至少包含：

| 字段 | 说明 |
|---|---|
| 决策日期 / 标的 / 方向 | 基础标识 |
| 结算窗口 | 5/10/20 日 |
| 分类 | 四分类之一 |
| 标的收益 vs 基准收益 | 跑赢/跑输幅度 |
| 归因 | FALSE_POSITIVE / REGIME_MISMATCH 必填 |
| 规则修订建议 | 有则写，无则留空 |

## 四、表达口径

- 说 `近 20 条看多建议方向正确率 55%，跑赢基准 8pp，样本未达晋升标准`。
- 不说 `我的策略胜率很高` / `这套方法稳定盈利`。
- 绩效数字必须带样本量与统计窗口，孤立的百分比禁止输出。
